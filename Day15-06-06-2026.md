## DevOps

### Nginx SSL Deployment on App Server 1

#### Task

Prepare App Server 1 for application deployment:

* Install Nginx
* Configure SSL using provided certificate and key
* Create index page
* Verify access over HTTPS

---

### Implementation Plan

Installed Nginx:

```bash
yum install -y nginx
```

Created SSL directory:

```bash
mkdir -p /etc/nginx/ssl
```

Moved provided files:

```bash
mv /tmp/nautilus.crt /etc/nginx/ssl/
mv /tmp/nautilus.key /etc/nginx/ssl/
```

Configured permissions:

```bash
chmod 600 /etc/nginx/ssl/nautilus.key
chmod 644 /etc/nginx/ssl/nautilus.crt
```

Created website content:

```bash
echo "Welcome!" > /usr/share/nginx/html/index.html
```

Configured Nginx SSL virtual host:

```nginx
server {
    listen 443 ssl;

    ssl_certificate /etc/nginx/ssl/nautilus.crt;
    ssl_certificate_key /etc/nginx/ssl/nautilus.key;

    location / {
        root /usr/share/nginx/html;
        index index.html;
    }
}
```

Validated:

```bash
nginx -t
```

Started service:

```bash
systemctl enable nginx
systemctl restart nginx
```

Verification:

```bash
curl -Ik https://stapp01
curl -k https://stapp01
```

Expected:

```text
HTTP/1.1 200 OK
Welcome!
```

---

### Learning

For SSL deployments:

```text
Certificate
+ Private Key
+ HTTPS Listener
+ Web Content
= Secure Web Server
```

# Key Lessons Learned

### DevOps

* SSL deployments require proper certificate placement and Nginx configuration.
* Always validate with `nginx -t` before restarting.

### MLOps

* DVC parameters are first-class dependencies.
* Changing parameters should only re-run affected stages.

### AWS

* Snapshot tasks frequently use existing resources.
* Always wait for snapshot state to become `completed`.

### Azure

* NSG rule priority determines traffic evaluation order.
* Exact rule names are often checked by validators.

### Terraform

* IAM resources are among the simplest and most common infrastructure objects to provision.
* The workflow remains:

```text
Write
→ Init
→ Plan
→ Apply
→ Verify
```
