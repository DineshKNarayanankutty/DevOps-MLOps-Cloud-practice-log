## Linux Administration

### Custom Apache User Creation

#### Task

Create a dedicated application user on App Server 2.

Requirements:

```text
Username       : kareem
UID            : 1794
Home Directory : /var/www/kareem
```

---

### Implementation

Connected to App Server 2:

```bash
ssh steve@stapp02
sudo su -
```

Created the user:

```bash
useradd -u 1794 -d /var/www/kareem -m kareem
```

---

### Validation

Verified UID:

```bash
id kareem
```

Expected:

```text
uid=1794(kareem)
```

Verified home directory:

```bash
grep "^kareem" /etc/passwd
```

Expected:

```text
kareem:x:1794:1794::/var/www/kareem:/bin/bash
```

Verified directory creation:

```bash
ls -ld /var/www/kareem
```

---

### Learning

Linux user structure:

```text
Username
    ↓
UID
    ↓
Home Directory
    ↓
Shell
```

Example:

```text
kareem
  ↓
UID 1794
  ↓
/var/www/kareem
  ↓
/bin/bash
```

---

### Security Concept Learned

Organizations often create dedicated users:

```text
apache_app1
apache_app2
nginx_blog
kareem
```

instead of running everything under:

```text
root
apache
```

Benefits:

* Better isolation
* Easier auditing
* Reduced blast radius if compromised
* Principle of Least Privilege

---

### Adding the Train Stage

Instead of manually editing `dvc.yaml`, DVC can generate the stage for us:

```bash
dvc stage add \
  -n train \
  -d data/processed/cleaned.csv \
  -d scripts/train.py \
  -p n_estimators,max_depth,test_size,random_seed \
  -o models/model.pkl \
  -o data/processed/test_split.csv \
  --metrics-no-cache metrics.json \
  python scripts/train.py
```

This automatically adds to `dvc.yaml`:

```yaml
train:
  cmd: python scripts/train.py
  deps:
    - data/processed/cleaned.csv
    - scripts/train.py
  params:
    - n_estimators
    - max_depth
    - test_size
    - random_seed
  outs:
    - models/model.pkl
    - data/processed/test_split.csv
  metrics:
    - metrics.json:
        cache: false
```

---

### Adding the Evaluate Stage

Again, DVC can create the YAML automatically:

```bash
dvc stage add \
  -n evaluate \
  -d models/model.pkl \
  -d data/processed/test_split.csv \
  -d scripts/evaluate.py \
  -O reports/evaluation.json \
  python scripts/evaluate.py
```

Notice:

```bash
-O
```

creates:

```yaml
outs:
  - reports/evaluation.json:
      cache: false
```

which means the evaluation report stays in Git instead of the DVC cache.

### Key Learning

The biggest takeaway from this task was learning that **DVC stages do not need to be written manually**.

Most production teams use:

```bash
dvc stage add
```

because it automatically updates:

```text

```

```bash

dvc status        # Check freshness
dvc push          # Upload artifacts

```
