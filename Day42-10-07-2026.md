# AWS

# Building a To-Do Application Backend with DynamoDB

## Objective

Create a DynamoDB table to store application tasks and perform basic CRUD-style operations by inserting and verifying task records.

Unlike relational databases, DynamoDB stores application data as **items** inside **tables** and provides extremely low-latency access at scale.

---

## Resource Created

```text
Service:
Amazon DynamoDB

Table:
datacenter-tasks

Primary Key:
taskId (String)
```

---

## Table Creation

Created the table using AWS CLI:

```bash
aws dynamodb create-table \
    --table-name datacenter-tasks \
    --attribute-definitions \
        AttributeName=taskId,AttributeType=S \
    --key-schema \
        AttributeName=taskId,KeyType=HASH \
    --billing-mode PAY_PER_REQUEST
```

### Configuration

```text
Table Name:
datacenter-tasks

Primary Key:
taskId

Data Type:
String

Billing Mode:
On-Demand (PAY_PER_REQUEST)
```

---

## Verification

Verified table creation:

```bash
aws dynamodb list-tables

aws dynamodb describe-table \
    --table-name datacenter-tasks
```

---

## Inserted Application Data

### Task 1

```bash
    --table-name datacenter-tasks \
```

---



```bash

    --destination /opt
```

Verified:

```bash
ls -l /opt
```

```bash

    --account-key "$ACCOUNT_KEY" \
    --name devops-blob-6995
```

```bash
    --account-name devopsst25828 \
    --account-key "$ACCOUNT_KEY" \
    --output table
```


## Cleanup Workflow

```text

      │
```

# Kubernetes

# Resource-Constrained Pod Deployment

## Objective

Deploy an Apache HTTP Server Pod with defined CPU and memory requests and limits.

---

## YAML Created

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: httpd-pod
spec:
  containers:
  - name: httpd-container
    image: httpd:latest
    resources:
      requests:
        memory: "15Mi"
        cpu: "100m"
      limits:
        memory: "20Mi"
        cpu: "100m"
```

---

## Deployment

Applied:

```bash
kubectl apply -f httpd-pod.yaml
```

---

## Verification

Checked Pod:

```bash
kubectl get pods
```

Inspected resources:

```bash
kubectl describe pod httpd-pod
```

Confirmed:

```text
Requests

CPU:
100m

Memory:
15Mi

Limits

CPU:
100m

Memory:
20Mi
```

---

## Scheduling Workflow

```text
Pod
      │
      ▼
Scheduler
      │
Uses Requests
      ▼
Node Selected
      │
Container Runs
      │
Memory
15Mi → 20Mi Maximum

CPU
100m Fixed
```

---

## Key Learning

Kubernetes schedules Pods based on **resource requests**, while **limits** prevent a container from consuming more resources than permitted.

# Automating Tasks with Cron

## Objective

Install the Cron service on every application server and schedule a recurring task for the root user.

---

## Servers Configured

```text
stapp01

stapp02

stapp03
```

---

## Installed Cron

```bash
yum install -y cronie

# or

dnf install -y cronie
```

---

## Enabled Service

```bash
systemctl enable crond

systemctl start crond
```

Verified:

```bash
systemctl status crond
```

Expected:

```text
Active: active (running)
```

---

## Configured Root Cron Job

Edited:

```bash
crontab -e
```

Added:

```cron
*/5 * * * * echo hello > /tmp/cron_text
```

Verified:

```bash
crontab -l
```

---

## Alternative Automation Method

Added the cron entry non-interactively:

```bash
(crontab -l 2>/dev/null; echo "*/5 * * * * echo hello > /tmp/cron_text") | crontab -
```

---

## Cron Execution Flow

```text
Cron Daemon
      │
Every 5 Minutes
      │
Execute
echo hello
      │
      ▼
/tmp/cron_text
```

---

## Key Learning

Cron is the standard Linux scheduler used for automating recurring administrative tasks such as backups, log rotation, monitoring scripts, and cleanup jobs.

# Biggest Lessons Today

### AWS

DynamoDB is a fully managed NoSQL database where data is stored as items identified by a primary key, making it highly scalable and suitable for modern cloud-native applications.

### Azure

Blob Storage cleanup should follow a safe workflow: verify the data has been copied successfully before deleting the source container to avoid accidental data loss.

### DevOps

Docker's `macvlan` networking enables containers to communicate on the physical network with their own MAC addresses, making them appear as independent hosts.

### Kubernetes

Resource **requests** influence scheduling decisions, while **limits** enforce maximum CPU and memory consumption, helping maintain cluster stability under load.

### Linux

Cron is a foundational automation tool in Linux. Properly configuring the `crond` service and root crontab enables reliable execution of repetitive operational tasks without manual intervention.
