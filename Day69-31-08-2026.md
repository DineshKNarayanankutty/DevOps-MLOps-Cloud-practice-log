# Kubernetes

## Task: Nginx Sidecar Container with Shared Logs

### Objective

Deploy an Nginx container together with a log-shipping sidecar container using a shared `emptyDir` volume.

### Requirements

```text
Pod: webserver

Main container:
  Name: nginx-container
  Image: nginx:latest

Sidecar:
  Name: sidecar-container
  Image: ubuntu:latest

Shared volume:
  Name: shared-logs
  Type: emptyDir

Nginx mount:
  /var/log/nginx

Sidecar mount:
  /var/log/nginx
```

### Pod Configuration

```yaml id="m5v7x2"
apiVersion: v1
kind: Pod
metadata:
  name: webserver
spec:
  volumes:
    - name: shared-logs
      emptyDir: {}

  initContainers:
    - name: sidecar-container
      image: ubuntu:latest
      restartPolicy: Always
      command: ["sh", "-c", "while true; do cat /var/log/nginx/access.log /var/log/nginx/error.log; sleep 30; done"]
      volumeMounts:
        - name: shared-logs
          mountPath: /var/log/nginx

  containers:
    - name: nginx-container
      image: nginx:latest
      volumeMounts:
        - name: shared-logs
          mountPath: /var/log/nginx
```

### Commands Used

Create the Pod:

```bash id="p9q3ks"
kubectl apply -f webserver.yaml
```

Verify:

```bash id="n6k3hf"
kubectl get pod webserver
```

Verify the containers:

```bash id="a7x5mr"
kubectl describe pod webserver
```

Generate an Nginx request:

```bash id="q5z1av"
kubectl exec webserver -c nginx-container -- curl -s http://localhost
```

Check the shared access log from the sidecar:

```bash id="w8c2jd"
kubectl exec webserver -c sidecar-container -- cat /var/log/nginx/access.log
```

### Key Learning

* Kubernetes supports long-running sidecars using `initContainers` with `restartPolicy: Always`.
* `emptyDir` can be shared between multiple containers in the same Pod.
* Nginx writes logs to the shared volume while the sidecar reads and ships/processes them.
* The sidecar pattern separates application serving from log-processing responsibilities.

# Terraform

## Task: SNS Topic with IAM Role and EC2 Publish Permission

### Objective

Create an SNS topic and configure an IAM role trusted by EC2, with a policy allowing the role to publish messages to the specific SNS topic.

### Requirements

```text id="m4w8qa"
SNS Topic: datacenter-sns-topic

IAM Role: datacenter-sns-role

IAM Policy: datacenter-sns-policy

Permission:
sns:Publish
```

### Files Used

```text id="u5r3yk"
main.tf
locals.tf
outputs.tf
```

### `locals.tf`

```hcl id="k9c6pm"
locals {
  KKE_SNS_TOPIC_NAME = "datacenter-sns-topic"
  KKE_ROLE_NAME      = "datacenter-sns-role"
  KKE_POLICY_NAME    = "datacenter-sns-policy"
}
```

### `main.tf`

Created the SNS topic:

```hcl id="z6n2pt"
resource "aws_sns_topic" "datacenter_sns_topic" {
  name = local.KKE_SNS_TOPIC_NAME
}
```

Created the IAM role with EC2 as trusted entity:

```hcl id="g2t8rm"
resource "aws_iam_role" "datacenter_sns_role" {
  name = local.KKE_ROLE_NAME

  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect = "Allow"
        Principal = {
          Service = "ec2.amazonaws.com"
        }
        Action = "sts:AssumeRole"
      }
    ]
  })
}
```

Created the SNS publish policy:

```hcl id="c7v4nx"
resource "aws_iam_policy" "datacenter_sns_policy" {
  name        = local.KKE_POLICY_NAME
  description = "Allows EC2 instances to publish messages to the SNS topic"

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect   = "Allow"
        Action   = "sns:Publish"
        Resource = aws_sns_topic.datacenter_sns_topic.arn
      }
    ]
  })
}
```

Attached the policy to the role:

```hcl id="r3m8ws"
resource "aws_iam_role_policy_attachment" "datacenter_sns_policy_attachment" {
  role       = aws_iam_role.datacenter_sns_role.name
  policy_arn = aws_iam_policy.datacenter_sns_policy.arn
}
```

### `outputs.tf`

```hcl id="v6p2az"
output "kke_sns_topic_name" {
  description = "Name of the SNS topic"
  value       = aws_sns_topic.datacenter_sns_topic.name
}

output "kke_role_name" {
  description = "Name of the IAM role"
  value       = aws_iam_role.datacenter_sns_role.name
}

output "kke_policy_name" {
  description = "Name of the IAM policy"
  value       = aws_iam_policy.datacenter_sns_policy.name
}
```

### Commands Used

```bash id="x8p4mc"
terraform init
terraform fmt
terraform validate
terraform plan
terraform apply
```

Verify outputs:

```bash id="q2v9hk"
terraform output kke_sns_topic_name
terraform output kke_role_name
terraform output kke_policy_name
```

Verify policy attachment:

```bash id="y7n5rs"
aws iam list-attached-role-policies \
  --role-name datacenter-sns-role
```

### Key Learning

* SNS topics provide publish/subscribe messaging.
* IAM roles can be trusted by EC2 using an assume-role policy.
* `sns:Publish` grants permission to publish messages.
* Restricting `Resource` to the specific SNS topic follows the least-privilege principle.
* Terraform `locals` can centralize reusable resource names.
* `aws_iam_role_policy_attachment` connects an IAM policy to an IAM role.
