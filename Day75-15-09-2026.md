### Step 5 — Diagnose App_server_1 launch failure

The SSH launch log showed:

```text
[SSH] Opening SSH connection to stapp01:22.
[SSH] Authentication successful.
```

Therefore:

```text
SSH connection       ✓
Authentication       ✓
SFTP                 ✓
Remote directory     ✓
```

The actual failure was:

```text
Error: LinkageError occurred while loading main class hudson.remoting.Launcher

java.lang.UnsupportedClassVersionError:
hudson/remoting/Launcher has been compiled by a more recent version
of the Java Runtime (class file version 61.0),
this version of the Java Runtime only recognizes class file versions
up to 55.0
```

Meaning:

```text
Required by Jenkins agent: Java 17
Installed/default Java:    Java 11
```

Java class-file versions:

```text
55 = Java 11
61 = Java 17
```

So the credentials were **not** the problem.

# Key troubleshooting lessons from today

## Jenkins

### SSH authentication successful but agent won't launch

Look beyond credentials.

If the log contains:

```text
Authentication successful
```

but:

```text
UnsupportedClassVersionError
```

check Java:

```bash
java -version
```

The Jenkins agent's Java runtime must support the class-file version required by the Jenkins remoting agent.

Today's case:

```text
Jenkins agent class version = 61
Java 17 = class version 61
Java 11 = class version 55
```

Therefore:

```text
Java 11 → insufficient
Java 17 → required
```

---

## MLOps

Debug the monitoring chain from the first failed hop:

```text
1. Is Evidently producing scores?
          ↓
2. Does metric-emitter expose /metrics?
          ↓
3. Is Prometheus scraping metric-emitter?
          ↓
4. Is Grafana connected to Prometheus?
          ↓
5. Do Grafana queries return samples?
```

Today's three bugs:

```text
Bug 1:
Flask route
/prom-metrics
        ↓
/metrics

Bug 2:
Prometheus
metric-emitter:8000
        ↓
metric-emitter:5000

Bug 3:
Grafana datasource
http://prometheus:9091
        ↓
http://prometheus:9090
```

The most important MLOps lesson:

```text
Evidently → Metric emitter → Prometheus → Grafana
```

A healthy upstream component does not guarantee the downstream monitoring pipeline works. Diagnose each hop independently using its observable symptom.
