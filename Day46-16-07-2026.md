# AWS

## Task 1: Automated File Transfer using Amazon S3, Lambda and DynamoDB

### Objective

Create an event-driven architecture where uploading a file to a public S3 bucket automatically triggers a Lambda function that copies the file to a private S3 bucket and logs the operation into a DynamoDB table.

### Architecture

```text
Public S3 Bucket
(datacenter-public-21357)
        │
ObjectCreated Event
        │
        ▼
 Lambda Function
(datacenter-copyfunction)
     ├──────────────► Private S3 Bucket
     │                  (Copied File)
     │
     └──────────────► DynamoDB
                     (Copy Logs)
```

### Resources Created

- Public S3 Bucket: `datacenter-public-21357`
- Private S3 Bucket: `datacenter-private-27590`
- Lambda Function: `datacenter-copyfunction`
- IAM Role: `lambda_execution_role`
- DynamoDB Table: `datacenter-S3CopyLogs`
- S3 Event Notification

### Steps Performed

1. Created a public S3 bucket.
2. Disabled Block Public Access.
3. Added bucket policy for public object access.
4. Created a private S3 bucket.
5. Created DynamoDB table.
6. Created IAM role with S3, DynamoDB and CloudWatch permissions.
7. Modified `lambda-function.py` placeholders.
8. Packaged the Lambda code.
9. Uploaded the ZIP package.
10. Configured the S3 trigger.
11. Uploaded `sample.zip`.
12. Verified file copy and DynamoDB logging.

### Commands Used

```bash
aws s3 mb s3://datacenter-public-21357

aws s3 mb s3://datacenter-private-27590

aws dynamodb create-table ...

zip function.zip lambda_function.py

aws lambda update-function-code \
--function-name datacenter-copyfunction \
--zip-file fileb:///root/function.zip

aws s3 cp /root/sample.zip s3://datacenter-public-21357/

aws s3 ls s3://datacenter-private-27590

aws dynamodb scan \
--table-name datacenter-S3CopyLogs
```

### Code Used

**Modified Portion of `lambda_function.py`**

```python
DYNAMODB_TABLE = "datacenter-S3CopyLogs"

PRIVATE_BUCKET = "datacenter-private-27590"
```

### Verification

```bash
aws s3 ls s3://datacenter-private-27590

aws dynamodb scan \
--table-name datacenter-S3CopyLogs
```

### Issues Encountered

#### Issue

Lambda function executed but file was not copied.

#### Cause

The deployment ZIP contained `lambda-function.py`, while the Lambda handler expected:

```text
lambda_function.lambda_handler
```

Python module names cannot contain hyphens.

#### Resolution

- Renamed:

```text
lambda-function.py
```

to

```text
lambda_function.py
```

- Recreated the ZIP.
- Uploaded the updated package.
- Lambda executed successfully.

### Key Learnings

- Lambda handler names must match the Python module filename exactly.
- Python module filenames cannot contain hyphens.
- `fileb://` is required when uploading Lambda ZIP files using AWS CLI.

### Resources Created

- CronJob: `nautilus`

### Steps Performed

1. Created the CronJob YAML.
2. Applied the manifest.
3. Verified deployment.

### Commands Used

```bash

kubectl get cronjobs

kubectl describe cronjob nautilus

kubectl get cronjob nautilus -o yaml
```

### Code Used

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: nautilus
spec:
  schedule: "*/11 * * * *"
  jobTemplate:
    spec:
      template:
        spec:
          restartPolicy: OnFailure
          containers:
          - name: cron-nautilus
            image: httpd:latest
            command:
            - /bin/sh
            - -c
            - "echo Welcome to xfusioncorp!"
```

### Verification

```bash

kubectl describe cronjob nautilus
```

### Key Learnings

- CronJobs use `jobTemplate` to define Jobs.
- Restart policy for CronJobs should be specified under the Pod template.
