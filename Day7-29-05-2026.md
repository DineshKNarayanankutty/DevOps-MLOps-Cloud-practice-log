# DevOps

## Password-less SSH Authentication Setup

### Task

Configured SSH key-based authentication from user `thor` on the jump host to all application servers using their respective sudo users.

---

### Switch to thor User

```bash
sudo su - thor
```

### Verify User

```bash
whoami
```

---

### Check Existing SSH Keys

```bash
ls -la ~/.ssh
```

---

### Generate RSA Key Pair (if not present)

```bash
ssh-keygen -t rsa
```

---

### Copy Public Key to App Server 1

```bash
ssh-copy-id tony@stapp01
```

### Copy Public Key to App Server 2

```bash
ssh-copy-id steve@stapp02
```

### Copy Public Key to App Server 3

```bash
ssh-copy-id banner@stapp03
```

---

### Verify Password-less Login

```bash
ssh tony@stapp01 hostname
ssh steve@stapp02 hostname
ssh banner@stapp03 hostname
```

---

### Simple Explanation

Instead of entering passwords every time, SSH keys allow secure authentication automatically.

The public key is copied to each server, while the private key remains on the jump host.

---

### Why This is Important

Password-less SSH is used extensively in:

* Ansible automation
* Backup scripts
* CI/CD pipelines
* Monitoring tools
* Remote administration
* Infrastructure automation

Without password-less authentication, automation tools cannot operate efficiently across multiple servers.

# MLOps

## Python Package Distribution using pyproject.toml

### Task

Converted the fraud-detection project into a standard Python package and generated an installable wheel distribution.

---

### Navigate to Project

```bash
cd /root/code/fraud-detection
```

---

### Edit pyproject.toml

```bash
vi pyproject.toml
```

---

### Final pyproject.toml

```toml
[build-system]
requires = ["setuptools>=61.0", "wheel"]
build-backend = "setuptools.build_meta"

[project]
name = "fraud_detection"
version = "0.1.0"
description = "Fraud detection model"
requires-python = ">=3.10"

dependencies = [
    "scikit-learn",
    "pandas",
    "numpy"
]

[tool.setuptools.packages.find]
where = ["src"]
```

---

### Build Package

```bash
python3 -m build
```

---

### Verify Build Artifacts

```bash
ls -l dist/
```

Expected:

```text
fraud_detection-0.1.0.tar.gz
fraud_detection-0.1.0-py3-none-any.whl
```

---

### Simple Explanation

A wheel (`.whl`) is Python's installable package format.

This allows the fraud-detection project to be installed like any other Python library.

---

### Why This is Important

Packaging enables:

* Reusable ML code
* Versioned releases
* Easy deployments
* CI/CD integration
* Artifact management
* Reproducible environments

This is a core MLOps practice used in production ML systems.

# Terraform

## Provision EC2 Instance with Key Pair

### Task

Created an AWS EC2 instance using Terraform with a custom RSA key pair and default security group.

---

### Navigate to Terraform Directory

```bash
cd /home/bob/terraform
```

---

### Create/Edit main.tf

```bash
vi main.tf
```

---

### Terraform Configuration

```hcl
resource "tls_private_key" "devops_kp" {
  algorithm = "RSA"
  rsa_bits  = 4096
}

resource "aws_key_pair" "devops_kp" {
  key_name   = "devops-kp"
  public_key = tls_private_key.devops_kp.public_key_openssh
}

data "aws_security_group" "default" {
  name = "default"
}

resource "aws_instance" "devops_ec2" {
  ami                    = "ami-0c101f26f147fa7fd"
  instance_type          = "t2.micro"
  key_name               = aws_key_pair.devops_kp.key_name
  vpc_security_group_ids = [data.aws_security_group.default.id]

  tags = {
    Name = "devops-ec2"
  }
}
```

---

### Initialize Terraform

```bash
terraform init
```

---

### Apply Terraform Configuration

```bash
terraform apply -auto-approve
```

---

### Verify Resources

```bash
terraform state list
```

Expected:

```text
aws_instance.devops_ec2
aws_key_pair.devops_kp
tls_private_key.devops_kp
```

---

### Simple Explanation

Terraform was used to:

* Generate an RSA key pair
* Create an AWS Key Pair
* Retrieve the default security group
* Launch an EC2 instance
* Tag the instance as `devops-ec2`

---

### Why This is Important

This demonstrates Infrastructure as Code (IaC) principles:

* Automated provisioning
* Repeatable deployments
* Version-controlled infrastructure
* Reduced manual cloud configuration
