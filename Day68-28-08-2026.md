# Kubernetes

## Task: Shared `emptyDir` Volume Between Multiple Containers

### Objective

Create a Kubernetes Pod with two Ubuntu containers sharing the same `emptyDir` volume and verify that data created by one container is accessible from the other.

### Requirements

```text
Pod: volume-share-nautilus

Container 1:
  Name: volume-container-nautilus-1
  Image: ubuntu:latest
  Mount: /tmp/blog

Container 2:
  Name: volume-container-nautilus-2
  Image: ubuntu:latest
  Mount: /tmp/cluster

Shared Volume:
  Name: volume-share
  Type: emptyDir
```

### Pod Configuration

```yaml id="6f3w2m"
apiVersion: v1
kind: Pod
metadata:
  name: volume-share-nautilus
spec:
  containers:
    - name: volume-container-nautilus-1
      image: ubuntu:latest
      command:
        - sleep
        - "3600"
      volumeMounts:
        - name: volume-share
          mountPath: /tmp/blog

    - name: volume-container-nautilus-2
      image: ubuntu:latest
      command:
        - sleep
        - "3600"
      volumeMounts:
        - name: volume-share
          mountPath: /tmp/cluster

  volumes:
    - name: volume-share
      emptyDir: {}
```

### Commands Used

Create the Pod:

```bash id="75yqpm"
kubectl apply -f volume-share.yaml
```

Verify:

```bash id="ujh85t"
kubectl get pod volume-share-nautilus
```

Access the first container:

```bash id="db9s2k"
kubectl exec -it volume-share-nautilus \
  -c volume-container-nautilus-1 -- /bin/bash
```

Create the shared file:

```bash id="64wzqm"
echo "Welcome to xFusionCorp Industries" > /tmp/blog/blog.txt
```

Verify from the first container:

```bash id="8j1u7g"
cat /tmp/blog/blog.txt
```

Exit:

```bash id="6q5p2w"
exit
```

Verify the same file from the second container:

```bash id="n4w7ka"
kubectl exec volume-share-nautilus \
  -c volume-container-nautilus-2 -- ls -l /tmp/cluster
```

```bash id="8h8lqx"
kubectl exec volume-share-nautilus \
  -c volume-container-nautilus-2 -- cat /tmp/cluster/blog.txt
```

Expected:

```text id="k8w9wq"
Welcome to xFusionCorp Industries
```

### Key Learning

* Multiple containers within the same Pod can share an `emptyDir` volume.
* Containers can mount the same volume at different paths.
* Data written to the shared volume by one container is accessible from the other container.
* `emptyDir` is suitable for temporary Pod-level shared storage.
* `sleep` keeps containers running for testing and interaction.

# Terraform

## Task: DynamoDB Table with Fine-Grained IAM Read-Only Access

### Objective

Create a DynamoDB table and restrict an IAM role to read-only access to that specific table using Terraform.

### Requirements

```text
DynamoDB Table: xfusion-table

IAM Role: xfusion-role

IAM Policy: xfusion-readonly-policy

Allowed Actions:
  dynamodb:GetItem
  dynamodb:Scan
  dynamodb:Query
```

### Files Used

```text id="2kjm9a"
main.tf
variables.tf
terraform.tfvars
outputs.tf
```

### `variables.tf`

```hcl id="8gkmxv"
variable "KKE_TABLE_NAME" {
  description = "Name of the DynamoDB table"
  type        = string
}

variable "KKE_ROLE_NAME" {
  description = "Name of the IAM role"
  type        = string
}

variable "KKE_POLICY_NAME" {
  description = "Name of the IAM policy"
  type        = string
}
```

### `terraform.tfvars`

```hcl id="t2oh70"
KKE_TABLE_NAME  = "xfusion-table"
KKE_ROLE_NAME   = "xfusion-role"
KKE_POLICY_NAME = "xfusion-readonly-policy"
```

### `main.tf`

Created the DynamoDB table:

```hcl id="4w0yjj"
resource "aws_dynamodb_table" "xfusion_table" {
  name         = var.KKE_TABLE_NAME
  billing_mode = "PAY_PER_REQUEST"
  hash_key     = "id"

  attribute {
    name = "id"
    type = "S"
  }
}
```

Created the IAM role:

```hcl id="k68hql"
resource "aws_iam_role" "xfusion_role" {
  name = var.KKE_ROLE_NAME

  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect = "Allow"
        Principal = {
          Service = "ec2.amazonaws.com"
        }
        Action = "sts:AssumeRole"
      }
    ]
  })
}
```

Created the read-only IAM policy:

```hcl id="7m1cax"
resource "aws_iam_policy" "xfusion_readonly_policy" {
  name        = var.KKE_POLICY_NAME
  description = "Read-only access to the xfusion DynamoDB table"

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect = "Allow"
        Action = [
          "dynamodb:GetItem",
          "dynamodb:Scan",
          "dynamodb:Query"
        ]
        Resource = aws_dynamodb_table.xfusion_table.arn
      }
    ]
  })
}
```

Attached the policy to the role:

```hcl id="18q98d"
resource "aws_iam_role_policy_attachment" "xfusion_policy_attachment" {
  role       = aws_iam_role.xfusion_role.name
  policy_arn = aws_iam_policy.xfusion_readonly_policy.arn
}
```

### `outputs.tf`

```hcl id="6qzjyd"
output "kke_dynamodb_table" {
  description = "Name of the DynamoDB table"
  value       = aws_dynamodb_table.xfusion_table.name
}

output "kke_iam_role_name" {
  description = "Name of the IAM role"
  value       = aws_iam_role.xfusion_role.name
}

output "kke_iam_policy_name" {
  description = "Name of the IAM policy"
  value       = aws_iam_policy.xfusion_readonly_policy.name
}
```

### Commands Used

```bash id="hr5y8j"
terraform init
```

```bash id="i0w1af"
terraform fmt
```

```bash id="f7w3on"
terraform validate
```

```bash id="v1r4d6"
terraform plan
```

```bash id="xv7nmb"
terraform apply
```

Check Terraform outputs:

```bash id="l7k0c4"
terraform output kke_dynamodb_table
terraform output kke_iam_role_name
terraform output kke_iam_policy_name
```

Verify DynamoDB:

```bash id="y3j2kq"
aws dynamodb describe-table --table-name xfusion-table
```

Verify IAM role:

```bash id="p3l5wc"
aws iam get-role --role-name xfusion-role
```

Verify attached policy:

```bash id="q7j9an"
aws iam list-attached-role-policies \
  --role-name xfusion-role
```

### Key Learning

* DynamoDB tables can be created with minimal configuration using `PAY_PER_REQUEST`.
* IAM policies should follow the principle of least privilege.
* `GetItem`, `Scan`, and `Query` provide read-only DynamoDB access.
* The policy was restricted to the specific table ARN instead of using `"*"`.
* Terraform resource references allow the IAM policy to dynamically reference the DynamoDB table ARN.
* IAM roles provide an identity that trusted AWS services can assume.
