# MLOps

# Parallel Training Performance Comparison Using MLflow

## Objective

Compare RandomForest training performance using a single CPU core versus all available CPU cores.

---

## Problem Identified

The script incorrectly configured:

```python
N_JOBS_VALUES = [1, 1]
```

which caused both runs to execute serially.

Additionally,

```python
mlflow.log_param("n_jobs", "all")
```

logged the same parameter value for every run.

---

## Code Changes

Updated

```python
N_JOBS_VALUES = [1, -1]
```

Updated

```python
mlflow.log_param("n_jobs", n_jobs)
```

---

## Execute Training

```bash

python3 src/models/train_parallel.py
```

---

# Configuring SELinux for Permanent Disablement

## Objective

Prepare App Server 1 for future SELinux configuration by permanently disabling SELinux without immediately changing the running system.

---

## Server

```text
Application Server 1
```

---

## Step 1: Install SELinux Packages

```bash
ssh app1

sudo yum install -y \
selinux-policy \
selinux-policy-targeted \
policycoreutils
```

Alternative

```bash
sudo dnf install -y \
selinux-policy \
selinux-policy-targeted \
policycoreutils
```

---

## Step 2: Configure SELinux

Edit

```bash
sudo vi /etc/selinux/config
```

Updated

```text
SELINUX=disabled

SELINUXTYPE=targeted
```

Alternative

```bash
sudo sed -i \
's/^SELINUX=.*/SELINUX=disabled/' \
/etc/selinux/config
```

---

## Step 3: Verify Configuration

```bash
grep "^SELINUX=" /etc/selinux/config
```

Expected

```text
SELINUX=disabled
```

---

## Important Note

Did **not** reboot the server.

Did **not** execute

```bash
setenforce 0
```

because the task only required SELinux to be disabled after the next scheduled reboot.

---

## Workflow

```text
Install Packages
      ↓
Edit Configuration
      ↓
SELINUX=disabled
      ↓
Scheduled Reboot
      ↓
SELinux Disabled
```

---

## Key Learning

SELinux runtime mode and configuration file are independent. Updating `/etc/selinux/config` changes the behavior after reboot, while the current runtime mode remains unchanged until the system restarts.

# Issues Encountered Today

### Amazon ECS

Initially, there was uncertainty about enabling **Private Registry Authentication** in the ECS Task Definition. Since the container image was stored in **Amazon ECR**, the correct configuration was to leave this option disabled and use the `ecsTaskExecutionRole` to authenticate and pull the image.

### MLOps

The parallel training comparison was ineffective because both training runs used `n_jobs=1`, and the MLflow parameter was hardcoded to `"all"`. Updating the configuration to `[1, -1]` and logging the actual `n_jobs` value allowed MLflow to distinguish the serial and parallel runs and accurately compare training times.

# Biggest Lessons Today

### AWS

Amazon ECR and Amazon ECS work together to provide a complete container deployment platform. ECR stores images securely, while ECS Fargate runs containers without requiring server management.

### Azure

Azure Blob Storage can be securely accessed from a virtual machine using storage account keys, enabling controlled file uploads without exposing the storage account publicly.

### DevOps

Docker image tags are lightweight references to the same underlying image, making them useful for versioning and deployment workflows without duplicating storage.

### MLOps

Parallel training with `n_jobs=-1` can significantly reduce model training time for CPU-intensive algorithms, and logging configuration parameters correctly in MLflow is essential for meaningful experiment comparisons.

### Terraform

Using variables to define resource names makes Terraform configurations reusable, easier to maintain, and adaptable across multiple environments.

### Linux

Permanently changing SELinux behavior involves modifying `/etc/selinux/config`; the new mode only takes effect after a reboot, which allows administrators to schedule the change during planned maintenance windows.
