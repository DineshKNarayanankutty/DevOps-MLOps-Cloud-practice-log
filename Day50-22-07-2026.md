# AWS

## Lab: Expand EC2 Root EBS Volume

### Objective

Increase the root EBS volume attached to the EC2 instance **xfusion-ec2** from **8 GiB** to **12 GiB** and make the additional space available to the operating system without recreating the instance.

---

## Architecture

```
AWS EC2
    │
    ├── xfusion-ec2
    │
    └── Root EBS Volume
            │
            ├── Original Size : 8 GiB
            └── Expanded Size : 12 GiB
```

---

## Step 1 – Locate EC2 Instance

Opened AWS Console

```
EC2
→ Instances
→ xfusion-ec2
```

Verified the attached EBS volume.

---

## Step 2 – Modify EBS Volume

```
EC2
→ Volumes
→ Attached Volume

Actions
→ Modify Volume
```

Changed

```
8 GiB

↓

12 GiB
```

Saved the modification.

---

## Step 3 – Connect to EC2

SSH Key

```
/root/xfusion-keypair.pem
```

Connection

```bash
chmod 400 /root/xfusion-keypair.pem

ssh -i /root/xfusion-keypair.pem ec2-user@<PUBLIC-IP>
```

---

## Step 4 – Verify Disk

```bash
lsblk
```

Checked filesystem

```bash
df -h /
```

---

## Step 5 – Expand Partition

For Nitro instances

```bash
sudo growpart /dev/nvme0n1 1
```

For Xen instances

```bash
sudo growpart /dev/xvda 1
```

---

## Step 6 – Expand Filesystem

For XFS

```bash
sudo xfs_growfs /
```

For ext4

```bash
sudo resize2fs /dev/xvda1
```

---

## Step 7 – Verify

```bash
df -h /
```

Verified the root partition reflected the increased capacity.

---

## Learning

* Increasing an EBS volume alone is not enough.
* The partition and filesystem must also be expanded inside the instance.
* This operation can be completed without stopping the EC2 instance.

# DevOps

## Lab: Kubernetes Resource Requests & Limits

### Objective

Create an HTTPD pod with defined CPU and memory requests and limits.

---

Created

```
Pod

httpd-pod
```

Container

```
httpd-container
```

Image

```
httpd:latest
```

---

## Resource Configuration

Requests

```
CPU

100m

Memory

15Mi
```

Limits

```
CPU

100m

Memory

20Mi
```

---

## YAML

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: httpd-pod

spec:
  containers:
  - name: httpd-container
    image: httpd:latest

    resources:
      requests:
        cpu: "100m"
        memory: "15Mi"

      limits:
        cpu: "100m"
        memory: "20Mi"
```

---

## Deployment

```bash
kubectl apply -f httpd-pod.yaml
```

Verification

```bash
kubectl describe pod httpd-pod
```

---

## Learning

Resource requests reserve compute resources while limits prevent excessive resource consumption.

# MLOps

## Lab: Build ML Training Docker Image

### Objective

Create a reproducible Docker image for the fraud-detection training environment.

---

## Dockerfile

```dockerfile
FROM python:3.11-slim

WORKDIR /app

RUN pip install --no-cache-dir \
scikit-learn \
pandas \
numpy \
joblib

COPY train.py /app/train.py

CMD ["python3","train.py"]
```

---

## Build

```bash
cd /root/code/ml-docker

docker build -t ml-trainer:v1 .
```

---

## Verify

```bash
docker images ml-trainer:v1
```

Repository ID
