# AWS

## Attach Elastic IP to EC2 Instance

### Steps

1. Login to AWS Console.
2. Switch to region:

```text
us-east-1
```

3. Open:

```text
EC2 → Elastic IPs
```

4. Select:

```text
xfusion-ec2-eip
```

5. Click:

```text
Actions → Associate Elastic IP address
```

6. In the association form:

* Resource type: **Instance**
* Instance: **xfusion-ec2**
* Private IP: leave default (or select the instance's primary private IP)

7. Click:

```text
Associate
```

---

### Verify

Go to:

```text
EC2 → Instances → xfusion-ec2
```

The **Public IPv4 address** should now show the Elastic IP.

Or check:

```text
EC2 → Elastic IPs
```

and verify that **xfusion-ec2-eip** shows:

```text
Associated instance: xfusion-ec2
```

---

### Why this is important

An **Elastic IP (EIP)** is a static public IP address. Associating it with an EC2 instance ensures:

* The public IP remains the same after instance stop/start cycles.
* DNS records and external clients can reliably reach the server.
* Production services have a stable endpoint.

# Azure 

##  Attach Public IP to Azure Virtual Machine

### Using Azure Portal

1. Open Azure Portal.
2. Go to:

```text
Virtual Machines
```

3. Select:

```text
xfusion-vm-pip
```

4. Under **Settings**, click:

```text
Networking
```

5. Click the attached Network Interface (NIC).

6. On the NIC page, go to:

```text
IP configurations
```

7. Select the existing IP configuration (usually `ipconfig1`).

8. Under **Public IP address**, choose:

```text
xfusion-pip
```

9. Click:

```text
Save
```

---

### Verify

Go back to:

```text
Virtual Machines → xfusion-vm-pip
```

You should now see:

```text
Public IP address: <IP from xfusion-pip>
```

or verify from:

```text
Network Interface → IP Configurations
```

where `ipconfig1` should show:

```text
Public IP address = xfusion-pip
```

---

### Azure CLI Alternative

First find the NIC attached to the VM:

```bash
az vm show \
  --name xfusion-vm-pip \
  --resource-group <resource-group> \
  --query "networkProfile.networkInterfaces[0].id" \
  -o tsv
```

Attach the Public IP:

```bash
az network nic ip-config update \
  --resource-group <resource-group> \
  --nic-name <nic-name> \
  --name ipconfig1 \
  --public-ip-address xfusion-pip
```

Verify:

```bash
az vm show \
  --name xfusion-vm-pip \
  --resource-group <resource-group> \
  -d \
  --query publicIps
```

# DevOps

## Website Content Backup Automation Script

### Task

Created a Bash script to archive website content from App Server 2 and copy it to the Nautilus Storage Server.

---

### Infrastructure

| Component      | Value    |
| -------------- | -------- |
| App Server     | stapp02  |
| User           | steve    |
| Storage Server | ststor01 |
| Storage User   | natasha  |

---

### Install zip Package

```bash
sudo yum install -y zip
```

or

```bash
sudo dnf install -y zip
```

---

### Configure Passwordless SSH

Generate SSH Key:

```bash
ssh-keygen -t rsa -N "" -f ~/.ssh/id_rsa
```

Copy Public Key:

```bash
ssh-copy-id natasha@ststor01
```

Verify:

```bash
ssh natasha@ststor01 hostname
```

---

### Create Required Directories

```bash
sudo mkdir -p /scripts
sudo mkdir -p /archives

sudo chown steve:steve /scripts
sudo chown steve:steve /archives
```

---

### Create Archive Script

```bash
vi /scripts/media_archive.sh
```

```bash
#!/bin/bash

zip -r /archives/xfusioncorp_media.zip /var/www/html/media

scp /archives/xfusioncorp_media.zip natasha@ststor01:/archives/
```

---

### Make Executable

```bash
chmod 755 /scripts/media_archive.sh
```

---

### Execute Script

```bash
/scripts/media_archive.sh
```

---

## What Went Wrong

### Issue #1

Initial script attempted to copy:

```bash
scp /archives natasha@ststor01:/archives/
```

instead of:

```bash
scp /archives/xfusioncorp_media.zip natasha@ststor01:/archives/
```

Result:

```text
scp: local "/archives" is not a regular file
```

---

### Resolution

Updated SCP command to reference the archive file itself:

```bash
scp /archives/xfusioncorp_media.zip natasha@ststor01:/archives/
```

---

### Issue #2

Archive appeared present but validator still failed.

Root cause:

* Script executed as root.
* Validator expects the application user (`steve`) to execute the script.
* Passwordless SSH keys needed to belong to `steve`.

---

### Resolution

Performed:

```bash
ssh-keygen
ssh-copy-id natasha@ststor01
```

as user:

```text
steve
```

and executed:

```bash
/scripts/media_archive.sh
```

as `steve`.

---

### Why This Is Important

This simulates a real-world backup workflow:

* Website backup creation
* Remote archive storage
* Passwordless automation
* Disaster recovery preparation

# Terraform

## Create AWS EBS Snapshot

### Task

Created a snapshot of an existing EBS volume named:

```text
xfusion-vol
```

Requirements:

```text
Snapshot Name: xfusion-vol-ss
Description: Xfusion Snapshot
```

---

### Initial Attempt

```hcl
data "aws_ebs_volume" "xfusion_vol" {
  filter {
    name   = "tag:Name"
    values = ["xfusion_vol"]
  }
}
```

---

### What Went Wrong

Terraform error:

```text
Your query returned no results.
```

Reason:

```text
xfusion_vol  ❌
xfusion-vol  ✅
```

Used underscore instead of hyphen.

---

### Resolution #1

Corrected filter:

```hcl
data "aws_ebs_volume" "xfusion_vol" {
  filter {
    name   = "tag:Name"
    values = ["xfusion-vol"]
  }
}
```

---

### Issue #2

Some KodeKloud AWS environments (LocalStack/mock AWS) may not return existing resources through data sources.

Even after correcting the tag, the lookup can fail.

---

### Resolution #2

Used Terraform-managed resource already present in state:

Check:

```bash
terraform state list
```

Verify:

```bash
terraform state show aws_ebs_volume.k8s_volume
```

Snapshot configuration:

```hcl
resource "aws_ebs_snapshot" "xfusion_vol_ss" {
  volume_id   = aws_ebs_volume.k8s_volume.id
  description = "Xfusion Snapshot"

  tags = {
    Name = "xfusion-vol-ss"
  }
}
```

---

### Apply Configuration

```bash
terraform apply -auto-approve
```

---

### Why This Is Important

Snapshots are used for:

* Backups
* Disaster Recovery
* Data Protection
* Volume Restoration
* Migration Workflows

Using Terraform ensures snapshot creation is automated and reproducible.
