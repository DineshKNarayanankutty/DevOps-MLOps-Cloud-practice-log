## Understanding This Task

### What is an RDS Snapshot?

An RDS snapshot is a point-in-time backup of an RDS database.

Workflow:

```text
Running Database
        │
        ▼
Take Snapshot
        │
        ▼
Snapshot Stored
```

---

### Why Restore?

Instead of experimenting on production:

```text
Production Database
        │
        ▼
Snapshot
        │
        ▼
Restore
        │
        ▼
Testing Database
```

This protects production data while validating upgrades and recovery procedures.

# DevOps

## Git Rebase

### Objective

Update the feature branch with the latest master changes **without creating a merge commit**.

---

### Commands Used

Navigate:

```bash
cd /usr/src/kodekloudrepos/demo
```

---

Fetch latest changes:

```bash
git fetch origin
```

---

Switch to feature branch:

```bash
git checkout feature
```

---

Rebase:

```bash
git rebase master
```

---

If conflicts occurred:

Check:

```bash
git status
```

Resolve conflicts.

Stage:

```bash
git add <resolved-file>
```

Continue:

```bash
git rebase --continue
```

Abort if required:

```bash
git rebase --abort
```

---

Push updated history:

```bash
git push origin feature --force
```

---

## Understanding This Task

### Before Rebase

```text
master
A──B──C

feature
     \
      D──E
```

---

### After Rebase

```text
master
A──B──C
        \
         D'──E'
```

Feature commits are replayed on top of the latest master.

---

### Why Not Merge?

Merge creates:

```text
A──B──C────M
     \    /
      D──E
```

where **M** is a merge commit.

The task explicitly required:

```text
No Merge Commit
```

---

### Real-World Use Cases

```text
Keeping Feature Branch Current
Maintaining Clean Commit History
Preparing Pull Requests
Avoiding Unnecessary Merge Commits
```

## Deterministic ML Training

### Objective

Ensure identical code and data always produce identical metrics.

---

### Problem

The trainer produced different results because randomness was not controlled.

Sources of randomness:

```text
Train/Test Split
Random Forest Training
```

---

### File Modified

```text
/root/code/fraud-detection/src/models/train.py
```

---

### Change 1

Original:

```python

    X,

    stratify=y
```

Updated:

## Secure File Transfer Using SCP

### Objective

Copy:

```text
/tmp/nautilus.txt.gpg
```

from the Jump Server to:

```text
/home/appdata
```

on App Server 2.

---

### Commands Used

Copy file:

```bash
scp /tmp/nautilus.txt.gpg <user>@stapp02:/home/appdata/
```

Example:

```bash
scp /tmp/nautilus.txt.gpg steve@stapp02:/home/appdata/
```

---

Verify:

```bash
ls -l /home/appdata
```

or

```bash
ls -l /home/appdata/nautilus.txt.gpg
```

---

## Understanding This Task

### What is SCP?

`scp` (**Secure Copy**) transfers files securely over SSH.

Workflow:

```text
Jump Host
     │
     │  SCP
     ▼
App Server 2
```

---

### Command Breakdown

```bash
scp /tmp/nautilus.txt.gpg steve@stapp02:/home/appdata/
```

```text
scp
 │
Secure Copy

Source File
 │
Remote User@Host
 │
Destination Directory
```

---

### Difference Between cp and scp

Local copy:

```bash
cp source destination
```

Remote copy:

```bash
scp source user@host:destination
```
