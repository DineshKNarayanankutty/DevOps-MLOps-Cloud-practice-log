# Azure Key Vault Encryption and Decryption

## Objective

Protect sensitive data using Azure Key Vault by creating an RSA-4096 key, encrypting a Base64-encoded file with RSA-OAEP, and decrypting it back to verify data integrity.

---

## Resources Created


---

## Configuration

```text

Standard

7 Days

```

---

## Access Policy

Granted:

```text
Get

List

Encrypt

Decrypt
```

---

## Commands Used

Verify identity:

```bash
az account show --query user.name -o tsv
```

Encode file:

```bash
base64 /root/SensitiveData.txt > /root/plaintext.b64
```

Encrypt:

```bash
PLAINTEXT=$(cat /root/plaintext.b64)

az keyvault key encrypt \
  --vault-name datacenter-30336 \
  --name datacenter-key \
  --algorithm RSA-OAEP \
  --value "$PLAINTEXT" \
  --query result \
  -o tsv > /root/EncryptedData.bin
```

Decrypt:

```bash
ENCRYPTED=$(cat /root/EncryptedData.bin)

az keyvault key decrypt \
  --vault-name datacenter-30336 \
  --name datacenter-key \
  --algorithm RSA-OAEP \
  --value "$ENCRYPTED" \
  --query result \
  -o tsv > /root/decrypted.b64
```

Decode:

```bash
base64 -d /root/decrypted.b64 > /root/DecryptedData.txt
```

Verify:

```bash
diff /root/SensitiveData.txt /root/DecryptedData.txt
```

---

## Issue Encountered

Received:

```text
Forbidden

The user does not have keys encrypt permission.
```

Resolution:

Retrieved current identity:

```bash
az account show --query user.name -o tsv
```

Added an Access Policy granting:

```text
Get

List

Encrypt

Decrypt
```

Waited for permission propagation before retrying encryption.

---

## Workflow

```text

        │

        │
        ▼
Azure Key Vault
(RSA-4096)
        │
Encrypt
        ▼

        │

```

---

## Key Learning

Azure Key Vault encrypts data using cryptographic keys but requires explicit key permissions. When using Vault Access Policies, missing `Encrypt` or `Decrypt` permissions result in `403 Forbidden` errors.

# Terraform

# Creating an AWS IAM Policy Using Variables

## Objective

Automate IAM Policy creation using Terraform while storing the policy name in a reusable variable.

---

## Directory

```text
/home/bob/terraform
```

---

## variables.tf

```hcl
variable "KKE_iampolicy" {
  description = "IAM Policy Name"
  type        = string
  default     = "iampolicy_mark"
}
```

---

## main.tf

```hcl
provider "aws" {
  region = "us-east-1"
}

resource "aws_iam_policy" "policy" {
  name = var.KKE_iampolicy

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = "*"
      Resource = "*"
    }]
  })

  tags = {
    Name = var.KKE_iampolicy
  }
}
```

---

## Commands Used

```bash
cd /home/bob/terraform

terraform validate

terraform apply -auto-approve

terraform state list
```

## Key Learning

# Issues Encountered Today

### Azure Key Vault Permissions

Encryption failed with a `403 Forbidden` error because the current identity lacked **Encrypt** permission on the Key Vault. The issue was resolved by identifying the current principal and granting **Get, List, Encrypt, and Decrypt** permissions through the Key Vault access policy.

### MLOps Pipeline Wiring

The training pipeline failed due to three wiring problems:

* The `Makefile` executed the stages in the wrong order.
* `select_model.py` selected models using `accuracy` instead of `f1_score`.
* `register.py` assigned the `production` alias instead of the required `staging` alias.

Correcting these issues allowed the pipeline to complete successfully.

# Biggest Lessons Today

### AWS

Successful public access to an EC2-hosted application depends on the combined configuration of networking, routing, public IP assignment, security groups, and the application service itself.

### Azure

Azure Key Vault enforces cryptographic permissions independently of Azure login status. Even authenticated users must have explicit key permissions to perform encryption and decryption operations.

### DevOps

Managing services inside containers follows the same Linux administration principles as physical or virtual servers, with configuration persistence tied to the container lifecycle.

### MLOps

End-to-end ML pipelines are sensitive to orchestration order and metadata consistency. Correct execution sequencing, metric selection, and model registry aliases are essential for reliable automation.

### Terraform

Separating resource names into variables improves reusability and maintainability, while `jsonencode()` provides a clean way to define IAM policy documents.

### Kubernetes

Deployments are the recommended abstraction for managing applications because they automatically maintain the desired number of Pods and simplify updates and recovery.
