# DevOps (Kubernetes)

## Task: Kubernetes Secret and Secret-Mounted Pod

### Objective

Create a generic Kubernetes Secret from an existing license/password file and mount it securely into a Fedora Pod.

### Requirements

* Secret: `beta`
* Source file: `/opt/beta.txt`
* Pod: `secret-datacenter`
* Container: `secret-container-datacenter`
* Image: `fedora:latest`
* Mount path: `/opt/apps`

### Commands Used

Check the existing secret file:

```bash
cat /opt/beta.txt
```

Create the generic Secret:

```bash
kubectl create secret generic beta --from-file=/opt/beta.txt
```

Verify the Secret:

```bash
kubectl get secret beta
```

### Pod Configuration

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: secret-datacenter
spec:
  containers:
    - name: secret-container-datacenter
      image: fedora:latest
      command:
        - sleep
        - "3600"
      volumeMounts:
        - name: beta-secret
          mountPath: /opt/apps
          readOnly: true
  volumes:
    - name: beta-secret
      secret:
        secretName: beta
```

Apply:

```bash
kubectl apply -f secret-datacenter.yaml
```

### Verification Commands

```bash
kubectl get pod secret-datacenter
```

```bash
kubectl exec -it secret-datacenter \
  -c secret-container-datacenter -- /bin/bash
```

Inside the container:

```bash
ls -l /opt/apps
cat /opt/apps/beta.txt
```

### Key Learning

* Kubernetes Secrets store sensitive configuration such as passwords, tokens and license information.
* `kubectl create secret generic --from-file` creates a Secret directly from a file.
* Secrets can be consumed as mounted files.
* `readOnly: true` prevents the container from modifying the mounted Secret.

# MLOps

## Task: Implement A/B Model Routing

### Objective

Implement traffic splitting between two fraud-detection model versions using Flask.

### Models

```text
model_v1.pkl → MODEL_V1
model_v2.pkl → MODEL_V2
```

Required traffic distribution:

```text
MODEL_V1 → 80%
MODEL_V2 → 20%
```

### Project Directory

```text
/root/code/serving/
```

### Routing Logic Implemented

```python
if random.random() < 0.8:
    model = MODEL_V1
    model_version = "v1"
else:
    model = MODEL_V2
    model_version = "v2"

is_fraud = int(model.predict(features)[0])

return jsonify({
    "is_fraud": is_fraud,
    "model_version": model_version
}), 200
```

### Commands Used

Start the Flask server:

```bash
cd /root/code/serving
python3 ab_server.py
```

Verify health:

```bash
curl -i http://localhost:8085/health
```

Test prediction:

```bash
curl -X POST http://localhost:8085/predict \
  -H "Content-Type: application/json" \
  -d '{"amount":3200,"hour":23,"num_tx_past_day":5}'
```

### Traffic Distribution Test

Generated 200 requests:

```bash
for i in $(seq 1 200); do
  curl -s -X POST http://localhost:8085/predict \
    -H "Content-Type: application/json" \
    -d '{"amount":3200,"hour":23,"num_tx_past_day":5}'
done > /tmp/predictions.json
```

Count v1:

```bash
grep -o '"model_version":"v1"' /tmp/predictions.json | wc -l
```

Count v2:

```bash
grep -o '"model_version":"v2"' /tmp/predictions.json | wc -l
```

### Key Learning

* A/B testing allows two model versions to receive production traffic simultaneously.
* Random routing can implement an approximate 80/20 traffic split.
* Every prediction response should identify the model version used.
* Model attribution is important for comparing model performance and detecting drift.

# Terraform – AWS

## Task: Create Protected S3 Bucket

### Objective

Create an S3 bucket dynamically using a Terraform variable and protect it from accidental destruction using the `prevent_destroy` lifecycle rule.

### Bucket

```text
nautilus-s3-3848
```

### Files Used

```text
main.tf
variables.tf
terraform.tfvars
outputs.tf
```

### `variables.tf`

```hcl
variable "KKE_BUCKET_NAME" {
  description = "Name of the S3 bucket"
  type        = string
}
```

### `terraform.tfvars`

```hcl
KKE_BUCKET_NAME = "nautilus-s3-3848"
```

### `main.tf`

```hcl
resource "aws_s3_bucket" "nautilus_bucket" {
  bucket = var.KKE_BUCKET_NAME

  lifecycle {
    prevent_destroy = true
  }
}
```

### `outputs.tf`

```hcl
output "s3_bucket_name" {
  description = "Name of the created S3 bucket"
  value       = aws_s3_bucket.nautilus_bucket.bucket
}
```

### Commands Used

```bash
terraform init
terraform fmt
terraform validate
terraform plan
terraform apply
terraform output s3_bucket_name
```

AWS verification:

```bash
aws s3api head-bucket --bucket nautilus-s3-3848
```

### Key Learning

* Terraform variables make resource names configurable.
* `terraform.tfvars` supplies variable values.
* `prevent_destroy = true` protects critical resources from accidental Terraform destruction.
* Terraform lifecycle rules are useful for production resources that must not be deleted accidentally.

# Linux

## Task: Archive Website Blog Content

### Objective

Create a Bash script on **App Server 2** to archive website blog content and copy the archive to the Nautilus Storage Server without requiring a password.

### Environment

```text
App Server: stapp02
User: steve
Storage Server: ststor01
Storage User: natasha
Source: /var/www/html/blog
Local archive: /archives/xfusioncorp_blog.zip
Remote archive: /archives/xfusioncorp_blog.zip
Script: /scripts/blog_archive.sh
```

## Step 1 — Install `zip` on App Server 2 (outside the script, as root)

```bash
ssh root@stapp02
yum install -y zip     # or apt-get install -y zip, depending on OS
```

## Step 2 — Set up passwordless SSH for `steve` (not root)

This is the part that broke last time — make sure you're actually operating as `steve`, and confirm it with `whoami`.

```bash
su - steve
whoami          # must print: steve
```

Now generate a key and copy it over, **as steve**:

```bash
ssh-keygen -t rsa -b 4096 -N "" -f ~/.ssh/id_rsa
ssh-copy-id natasha@ststor01
```

Verify — this must log in with **zero password prompt**:

```bash
ssh natasha@ststor01 whoami
# should print: natasha
```

If it still prompts for a password here, stop and fix this before moving on — nothing downstream will work otherwise.

## Step 3 — Create the directories

```bash
exit   # back to root
mkdir -p /scripts /archives
chown steve:steve /scripts /archives

ssh natasha@ststor01 "mkdir -p /archives && chown natasha:natasha /archives"
```

## Step 4 — Create `/scripts/blog_archive.sh`

```bash
#!/bin/bash

cd /var/www/html
zip -r /archives/xfusioncorp_blog.zip blog
scp /archives/xfusioncorp_blog.zip natasha@ststor01:/archives/
```

Using `cd /var/www/html` before zipping keeps the archive's internal paths as `blog/...` rather than the full `var/www/html/blog/...` — this is what most of these lab checkers expect when they say "zip archive of `/var/www/html/blog` directory."

## Step 5 — Permissions

```bash
chmod +x /scripts/blog_archive.sh
chown steve:steve /scripts/blog_archive.sh
```

## Step 6 — Run and verify as `steve` (not root)

```bash
su - steve -c "/scripts/blog_archive.sh"
```

Then immediately verify both copies exist, before touching the grader:

```bash
ls -l /archives/xfusioncorp_blog.zip
unzip -l /archives/xfusioncorp_blog.zip      # confirm it shows blog/... not var/www/html/blog/...
ssh natasha@ststor01 "ls -l /archives/xfusioncorp_blog.zip"
```

### Important Issue Solved

The previous attempts failed because the script needed to be executable by the **respective application-server user**, and passwordless SSH needed to be configured for that same user.

The successful flow was:

```text
steve
  ↓
/scripts/blog_archive.sh
  ↓
zip website content
  ↓
/archives/xfusioncorp_blog.zip
  ↓
passwordless SSH/SCP
  ↓
natasha@ststor01:/archives/
```

### Important Archive Detail

We used:

```bash
cd /var/www/html
zip -r /archives/xfusioncorp_blog.zip blog
```

instead of directly passing the absolute directory to `zip`.

This produces archive entries such as:

```text
blog/...
```

rather than unnecessarily embedding:

```text
var/www/html/blog/...
```

### Key Learning

* The script must run successfully as the designated application-server user.
* Passwordless SSH must be configured for that same user.
* `sudo` should not be placed inside the automation script.
* `zip` should be installed manually as required by the task.
* `scp` can securely transfer the generated archive to the storage server.
* Always verify both the local and remote archive before running the lab checker.
