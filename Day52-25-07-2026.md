# Part 1: DevOps Task – Kubernetes Deployment Rollback

## Objective

The Nautilus DevOps team deployed a new version of an application, but a customer reported a bug after the release. The goal was to roll back the deployment to the previous stable revision.

---

## Environment

* Platform: Kubernetes
* Deployment Name: `nginx-deployment`
* Tool Used: `kubectl`

---

## Step 1: Verify the deployment

```bash
kubectl get deployments
```

Confirmed that the deployment `nginx-deployment` exists.

---

## Step 2: Check rollout history

```bash
kubectl rollout history deployment/nginx-deployment
```

Purpose:

* Display all deployment revisions.
* Identify the current and previous revisions.

Example output:

```
deployment.apps/nginx-deployment
REVISION  CHANGE-CAUSE
1
2
```

---

## Step 3: Roll back to the previous revision

```bash
kubectl rollout undo deployment/nginx-deployment
```

Kubernetes reverted the deployment to the immediately previous revision.

---

## Step 4: Monitor rollback status

```bash
kubectl rollout status deployment/nginx-deployment
```

Expected output:

```
deployment "nginx-deployment" successfully rolled out
```

---

## Step 5: Verify deployment

```bash
kubectl get deployment nginx-deployment
```

Verify:

* Desired replicas
* Current replicas
* Available replicas

---

## Step 6: Verify Pods

```bash
kubectl get pods
```

Ensure:

* New Pods created
* Old Pods terminated
* All Pods in Running state

---

## Verification Commands

```bash
kubectl rollout history deployment/nginx-deployment

kubectl describe deployment nginx-deployment

kubectl get pods

kubectl rollout status deployment/nginx-deployment
```

---

## Learning

### Kubernetes Rollback

Rollback restores the previous ReplicaSet without manually changing the Deployment YAML.

Useful commands:

```bash
kubectl rollout history deployment/<deployment>

kubectl rollout undo deployment/<deployment>

kubectl rollout status deployment/<deployment>
```

# Part 2: MLOps Task – Docker Compose Local ML Development Stack

## Objective

Fix the Docker Compose configuration so all three services become accessible on their standard browser ports.

Services:

* Jupyter Lab
* MLflow
* SeaweedFS

---

## Project Location

```text
/root/code/ml-dev/
```

Files:

```
docker-compose.yml
```

---

## Initial Verification

Start the stack

```bash
docker compose -f /root/code/ml-dev/docker-compose.yml up -d
```

Check service status

```bash
docker compose -f /root/code/ml-dev/docker-compose.yml ps
```

Initially, the services were not reachable on their required ports.

---

## Problems Identified

### 1. SeaweedFS Port Mapping

SeaweedFS exposes:

* Container Port **8333** → S3 API
* Container Port **8888** → Filer UI

Required Host Ports

| Host | Container | Purpose  |
| ---- | --------- | -------- |
| 9000 | 8333      | S3 API   |
| 9001 | 8888      | Filer UI |

Incorrect mapping prevented browser access.

Correct mapping:

```yaml
ports:
  - "9000:8333"
  - "9001:8888"
```

---

### 2. Jupyter Authentication

The notebook required a token, preventing direct browser access.

Disabled authentication by modifying the compose configuration.

Example:

```yaml
command:
  - start-notebook.py
  - --IdentityProvider.token=''
  - --PasswordIdentityProvider.hashed_password=''
```

(Equivalent command depends on the Jupyter image version.)

---

### 3. MLflow Port

Verified that MLflow exposes:

```yaml
5000:5000
```

No further modification was required.

---

## Restart the Stack

After updating the compose file:

```bash
docker compose -f /root/code/ml-dev/docker-compose.yml down
```

Bring the stack back up


# Key Learnings

### Kubernetes

* Rollout history helps inspect deployment revisions.
* `kubectl rollout undo` restores the previous stable version.
* Always verify rollback status and Pod health after reverting.

### Docker Compose / MLOps

* Correct host-to-container port mapping is essential for service accessibility.
* Jupyter authentication can be disabled for local development by configuring startup arguments.
* SeaweedFS exposes separate ports for the S3 API and the Filer UI, both of which must be mapped correctly.
* Validate service health with both `docker compose ps` and HTTP checks (`curl`) before considering the deployment complete.
