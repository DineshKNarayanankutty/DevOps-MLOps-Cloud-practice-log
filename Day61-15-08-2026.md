## Kubernetes

### Task: Init Container Deployment

**Objective:** Create a Deployment using an init container to prepare shared data before the main container starts.

**Resources:**

* Deployment: `ic-deploy-xfusion`
* Init container: `ic-msg-xfusion`
* Main container: `ic-main-xfusion`
* Image: `debian:latest`
* Volume: `ic-volume-xfusion`
* Volume type: `emptyDir`
* Replica: `1`

**Code used:**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: ic-deploy-xfusion
spec:
  replicas: 1
  selector:
    matchLabels:
      app: ic-xfusion
  template:
    metadata:
      labels:
        app: ic-xfusion
    spec:
      initContainers:
        - name: ic-msg-xfusion
          image: debian:latest
          command:
            - /bin/bash
            - -c
            - "echo Init Done - Welcome to xFusionCorp Industries > /ic/ecommerce"
          volumeMounts:
            - name: ic-volume-xfusion
              mountPath: /ic

      containers:
        - name: ic-main-xfusion
          image: debian:latest
          command:
            - /bin/bash
            - -c
            - "while true; do cat /ic/ecommerce; sleep 5; done"
          volumeMounts:
            - name: ic-volume-xfusion
              mountPath: /ic

      volumes:
        - name: ic-volume-xfusion
          emptyDir: {}
```

**Commands used:**

```bash
kubectl apply -f ic-deploy-xfusion.yaml
kubectl get deployment ic-deploy-xfusion
kubectl get pods -l app=ic-xfusion
kubectl get pods -l app=ic-xfusion -o name
kubectl logs <pod-name> -c ic-msg-xfusion
kubectl logs <pod-name> -c ic-main-xfusion
```

**Key learning:** Init containers run before the main container and can prepare shared `emptyDir` volumes for the application.

# Terraform – AWS

### Task: Migrate S3 Data to a New Bucket

**Objective:** Create a new private S3 bucket using Terraform and migrate all data from the existing bucket.

**Source bucket:**

```text
xfusion-s3-7286
```

**Destination bucket:**

```text
xfusion-sync-6981
```

**Terraform state already contained:**

```text
aws_s3_bucket.wordpress_bucket
aws_s3_bucket_acl.wordpress_bucket_acl
```

### `variables.tf`

```hcl
variable "KKE_BUCKET" {
  description = "Name of the new S3 bucket"
  type        = string
  default     = "xfusion-sync-6981"
}
```

### `main.tf`

Existing bucket retained and new bucket/migration resources added:

```hcl
resource "aws_s3_bucket" "wordpress_bucket" {
  bucket = "xfusion-s3-7286"
}

resource "aws_s3_bucket_acl" "wordpress_bucket_acl" {
  bucket = aws_s3_bucket.wordpress_bucket.id
  acl    = "private"
}

resource "aws_s3_bucket" "sync_bucket" {
  bucket = var.KKE_BUCKET
}

resource "aws_s3_bucket_acl" "sync_bucket_acl" {
  bucket = aws_s3_bucket.sync_bucket.id
  acl    = "private"
}

resource "null_resource" "s3_data_migration" {
  depends_on = [
    aws_s3_bucket_acl.sync_bucket_acl
  ]

  triggers = {
    source_bucket      = aws_s3_bucket.wordpress_bucket.bucket
    destination_bucket = aws_s3_bucket.sync_bucket.bucket
  }

  provisioner "local-exec" {
    command = "aws s3 sync s3://${aws_s3_bucket.wordpress_bucket.bucket} s3://${aws_s3_bucket.sync_bucket.bucket} --delete"
  }
}
```

### `outputs.tf`

```hcl
output "new_kke_bucket_name" {
  description = "Name of the newly created S3 bucket"
  value       = aws_s3_bucket.sync_bucket.bucket
}

output "new_kke_bucket_acl" {
  description = "ACL of the newly created S3 bucket"
  value       = aws_s3_bucket_acl.sync_bucket_acl.acl
}
```

**Commands used:**

```bash
terraform fmt
terraform validate
terraform plan
terraform apply
terraform output
terraform output new_kke_bucket_name
terraform output new_kke_bucket_acl
```

**S3 verification:**

```bash
aws s3 ls s3://xfusion-s3-7286 --recursive
aws s3 ls s3://xfusion-sync-6981 --recursive
```

Consistency check:

```bash
aws s3 sync \
  s3://xfusion-s3-7286 \
  s3://xfusion-sync-6981 \
  --dryrun
```

**Key learning:** `aws s3 sync --delete` can synchronize the destination with the source, while Terraform manages the destination bucket and its configuration.
