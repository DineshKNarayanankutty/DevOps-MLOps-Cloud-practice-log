# DevOps

## Cron Job Automation Across App Servers

### Task

Installed and configured cron service (`crond`) on all app servers and created a scheduled job for the root user.

---

### Install Cron Service

```bash id="uj48"
yum install -y cronie
```

Alternative:

```bash id="uj49"
dnf install -y cronie
```

### Start Cron Service

```bash id="uj50"
systemctl start crond
```

### Enable Cron on Boot

```bash id="uj51"
systemctl enable crond
```

### Verify Service Status

```bash id="uj52"
systemctl status crond
```

---

### Configure Root Cron Job

```bash id="uj53"
crontab -e
```

Add:

```cron id="uj54"
*/5 * * * * echo hello > /tmp/cron_text
```

### Verify Cron Job

```bash id="uj55"
crontab -l
```

### Verify Output

```bash id="uj56"
cat /tmp/cron_text
```

---

### Simple Explanation

A cron job is a scheduled automated task in Linux.

This job runs every 5 minutes and writes:

```text id="uj57"
hello
```

into:

```text id="uj58"
/tmp/cron_text
```

---

### Why This is Important

Cron jobs are heavily used in real DevOps environments for:

* backups,
* log cleanup,
* monitoring,
* automation scripts,
* health checks,
* scheduled deployments.

Learning cron is foundational for Linux and DevOps automation.

## Allocate AWS Elastic IP using Terraform

### Task

Created an AWS Elastic IP resource using Terraform.

---

### Navigate to Terraform Directory

```bash id="uj68"
cd /home/bob/terraform
```

---

### Create/Edit main.tf

```bash id="uj69"
vi main.tf
```

---

### Terraform Elastic IP Configuration

```hcl id="uj70"
resource "aws_eip" "xfusion_eip" {
  domain = "vpc"

  tags = {
    Name = "xfusion-eip"
  }
}
```

---

### Initialize Terraform

```bash id="uj71"
terraform init
```

---

### Apply Terraform Configuration

```bash id="uj72"
terraform apply -auto-approve
```

---

### Verify Terraform State

```bash id="uj73"
terraform state list
```

---

### Simple Explanation

An Elastic IP is a static public IP address in AWS.

Unlike normal public IPs:

* Elastic IPs remain fixed,
* they can be reassigned to resources,
* useful for stable infrastructure access.

Terraform was used to automate the creation process.

---

### Why This is Important

Elastic IPs are commonly used for:

* production servers,
* load balancers,
* NAT gateways,
* fixed external access.

Using Terraform ensures:

* repeatable infrastructure,
* version-controlled cloud resources,
* Infrastructure as Code (IaC) practices.
