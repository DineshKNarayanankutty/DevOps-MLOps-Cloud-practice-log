# DevOps (Kubernetes)

## Task: Implement the Sidecar Pattern for Nginx Log Shipping

### Objective

Deploy a Kubernetes Pod using the **Sidecar Pattern** to collect Nginx access and error logs. The Pod should contain an Nginx web server and a sidecar container sharing an `emptyDir` volume mounted at `/var/log/nginx`.

---

## Environment

* Platform: Kubernetes
* Pod: `webserver`
* Main Container:

  * `nginx-container`
  * Image: `nginx:latest`
* Sidecar Container:

  * `sidecar-container`
  * Image: `ubuntu:latest`
* Shared Volume:

  * `shared-logs`
  * Type: `emptyDir`

---

## Step 1: Analyze the Requirement

Initially, the task required:

* An **init container** named `sidecar-container`
* Running an infinite loop
* All containers must remain in the **Running** state

This revealed an inconsistency because a traditional init container must complete before the main container starts, whereas an infinite loop prevents the Pod from progressing beyond the **Init** phase.

---

## Step 2: Initial Pod Manifest

Created the Pod using a regular sidecar container.

```yaml
volumes:
- name: shared-logs
  emptyDir: {}

containers:
- name: nginx-container
  image: nginx:latest

- name: sidecar-container
  image: ubuntu:latest
```

The validator reported:

```text
'sidecar-container' doesn't exist
Image used is not 'ubuntu:latest'
```

The validation expected `sidecar-container` under `initContainers`.

---

## Step 3: Update Using Native Sidecar

Modified the Pod manifest by defining the sidecar as an init container with:

```yaml
restartPolicy: Always
```

```yaml
initContainers:
- name: sidecar-container
  image: ubuntu:latest
  restartPolicy: Always
  command:
    - sh
    - -c
    - |
      while true; do
        cat /var/log/nginx/access.log \
            /var/log/nginx/error.log
        sleep 30
      done
```

This configuration follows Kubernetes' **native sidecar container** pattern.

---

## Step 4: Observe Pod State

Verified the Pod.

```bash
kubectl get pods
```

Observed:

```text
webserver   0/1   Init:0/1
```

Investigated the behavior and confirmed that long-running init containers require native sidecar support in the Kubernetes cluster.

---

## Verification Commands

```bash
kubectl apply -f webserver.yaml

kubectl get pods

kubectl describe pod webserver

kubectl logs webserver \
-c sidecar-container
```

---

## Key Learning

* Traditional init containers must terminate before application containers start.
* Kubernetes native sidecars use:

  * `initContainers`
  * `restartPolicy: Always`
* Native sidecar functionality depends on Kubernetes version and feature support.
* `emptyDir` is ideal for temporary log sharing between containers within the same Pod.

# Linux

## Task: Configure Firewalld for Apache and Nginx

### Objective

Configure `firewalld` on App Server 2 to:

* Allow incoming traffic on Nginx port `80`
* Block Apache port `8085`
* Use permanent firewall rules in the `public` zone
* Ensure Apache and Nginx services are running

---

## Environment

Server:

```text
App Server 2
```

Firewall:

```text
firewalld
```

Services:

* nginx
* httpd

---

## Step 1: Install and Enable Firewalld

Installed the package.

```bash
yum install -y firewalld
```

Enabled and started the service.

```bash
systemctl enable --now firewalld
```

Verified the service.

```bash
systemctl status firewalld
```

---

## Step 2: Configure Firewall Rules

Allowed HTTP permanently.

```bash
firewall-cmd \
--permanent \
--zone=public \
--add-port=80/tcp
```

Removed Apache port.

```bash
firewall-cmd \
--permanent \
--zone=public \
--remove-port=8085/tcp
```

Reloaded firewall.

```bash
firewall-cmd --reload
```

---

## Step 3: Start Services

Started Apache.

```bash
systemctl start httpd
```

Attempted to start Nginx.

```bash
systemctl start nginx
```

Received the error:

```text
bind() to 0.0.0.0:80 failed
Address already in use
```

---

## Step 4: Troubleshooting

Investigated port usage.

```bash
ss -tlnp | grep :80
```

Reviewed Apache listening ports.

```bash
grep -R "^Listen" \
/etc/httpd/conf \
/etc/httpd/conf.d
```

Validated Nginx configuration.

```bash
nginx -t
```

Checked Nginx status.

```bash
systemctl status nginx -l
```

The investigation indicated that another process was already listening on port `80`, preventing Nginx from binding successfully.

---

## Verification Commands

```bash
systemctl status firewalld

firewall-cmd \
--zone=public \
--list-ports

systemctl status nginx

systemctl status httpd

ss -tlnp
```

---

## Key Learning

* Only one service can bind to a TCP port at a time.
* Nginx reverse proxy deployments require Apache to listen on a different port (such as `8085`).
* `nginx -t` should always be executed before restarting the service.
* Firewall configuration alone does not guarantee service reachability; the service must also bind successfully to the intended port.

# MLOps

## Task: Configure Docker HEALTHCHECK for a Flask Inference API

### Objective

Update the Dockerfile for a Flask-based inference service to expose the correct application port and implement a functional Docker health check.

---

## Environment

Project Directory:

```text
/root/code/ml-health/
```

Image:

```text
ml-health:v1
```

Container:

```text
ml-health-api
```

Application Port:

```text
8085
```

---

## Initial Problems

The Dockerfile contained two issues.

### Incorrect Health Endpoint

```dockerfile
HEALTHCHECK

http://localhost:8085/healthz
```

The application actually served:

```text
/health
```

---

### Missing EXPOSE Instruction

The image did not advertise its listening port.

---

## Step 1: Update Dockerfile

Added:

```dockerfile
EXPOSE 8085
```

Updated the health check.

```dockerfile
HEALTHCHECK \
CMD python3 -c \
"import urllib.request;
urllib.request.urlopen(
'http://localhost:8085/health'
)"
```

---

## Step 2: Build Image

```bash
docker build \
-t ml-health:v1 .
```

---

## Step 3: Run Container

```bash
docker run -d \
--name ml-health-api \
-p 8085:8085 \
ml-health:v1
```

---

## Step 4: Verify Health

Checked Docker health.

```bash
docker inspect \
--format='{{.State.Health.Status}}' \
ml-health-api
```

Expected:

```text
healthy
```

Verified image metadata.

```bash
docker inspect \
--format '{{.Config.ExposedPorts}}' \
ml-health:v1
```

Expected:

```text
map[8085/tcp:{}]
```

Verified endpoint.

```bash
curl http://localhost:8085/health
```

Expected:

```json
{"status":"ok"}
```

---

## Key Learning

* Docker `HEALTHCHECK` should target an actual application endpoint.
* `EXPOSE` documents the intended listening port but does not publish it.
* Docker automatically updates container health status based on the configured health check.

## Task: Provision a Private AWS Infrastructure

### Objective

Provision a private AWS environment consisting of a VPC, subnet, security group, and EC2 instance using Terraform.

---

## Files Created


---

## Resources Created

### VPC

```hcl
resource "aws_vpc" "datacenter_vpc" {
  cidr_block           = var.KKE_VPC_CIDR
  enable_dns_support   = true
  enable_dns_hostnames = true

  tags = {
    Name = "devops-priv-vpc"
  }
}
```

---

### Private Subnet

```hcl
resource "aws_subnet" "datacenter_subnet" {
  vpc_id                  = aws_vpc.datacenter_vpc.id
  cidr_block              = var.KKE_SUBNET_CIDR
  map_public_ip_on_launch = false

  tags = {
    Name = "devops-priv-subnet"
  }
}
```

---

### Security Group

```hcl
resource "aws_security_group" "private_sg" {
  name        = "devops-priv-sg"
  description = "Allow traffic only from VPC"
  vpc_id      = aws_vpc.datacenter_vpc.id

  ingress {
    from_port   = 0
    to_port     = 65535
    protocol    = "tcp"
    cidr_blocks = [var.KKE_VPC_CIDR]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = {
    Name = "devops-priv-sg"
  }
}
```

---

### Amazon Linux AMI

```hcl
data "aws_ami" "amazon_linux" {
  most_recent = true

  owners = ["amazon"]

  filter {
    name   = "name"
    values = ["al2023-ami-*-x86_64"]
  }
}
```

---

### EC2 Instance

```hcl
resource "aws_instance" "private_ec2" {
  ami                         = data.aws_ami.amazon_linux.id
  instance_type               = "t2.micro"
  subnet_id                   = aws_subnet.datacenter_subnet.id
  vpc_security_group_ids       = [aws_security_group.private_sg.id]
  associate_public_ip_address  = false

  tags = {
    Name = "devops-priv-ec2"
  }
}
```

---

# Overall Key Learnings

## DevOps & Kubernetes

* Native sidecar containers are implemented through `initContainers` with `restartPolicy: Always`.
* Shared `emptyDir` volumes provide efficient temporary storage between containers in the same Pod.

## Linux

* Firewall rules and service configuration must work together to make services reachable.
* Port binding conflicts are a common cause of web server startup failures.

## MLOps

* Docker health checks provide continuous application health monitoring.
* `EXPOSE` documents container networking and helps downstream tooling understand intended service ports.

## Terraform

* Private AWS infrastructure can be created by combining VPCs, private subnets, security groups, and EC2 instances.
* Restricting security group ingress to the VPC CIDR improves network isolation and security.
