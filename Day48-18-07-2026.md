# Azure

## Topic: Azure Container Registry, Docker Image and Blob Storage Troubleshooting

### Objective

Resolved the Azure application deployment issue that resulted in an **Internal Server Error (500)**.

### Steps Performed

1. Checked Docker container logs.

```bash
docker logs python-app
```

2. Identified the application error.

```
FileNotFoundError:
config.json
```

3. Verified that `config.json` existed on the host.

```bash
ls
cat config.json
```

4. Compared the application code with the Dockerfile.

Application expected:

```python
with open("config.json","r")
```

Docker image contained only:

```dockerfile
COPY app.py .
```

5. Determined that the Docker image did not include `config.json`.

6. Updated the Dockerfile.

```dockerfile
FROM python:3.9-slim

WORKDIR /app

COPY app.py .
COPY config.json .

RUN pip install flask

EXPOSE 80

CMD ["python","app.py"]
```

7. Rebuilt the Docker image.

```bash
docker build -t datacenter/python-app:latest .
```

8. Tagged the image.

```bash
docker tag datacenter/python-app:latest \
datacenteracr30712.azurecr.io/datacenter/python-app:latest
```

9. Logged into Azure Container Registry.

```bash
az acr login --name datacenteracr30712
```

10. Pushed the updated image.

```bash
docker push datacenteracr30712.azurecr.io/datacenter/python-app:latest
```

11. Planned to redeploy the updated image on the Azure VM.

### Root Cause

The Flask application expected a local `config.json` file, while the Docker image copied only `app.py`.

### Key Learning

* Always compare application expectations with Docker image contents.
* Azure Blob Storage creation does not automatically make files available inside containers.
* Container logs are the fastest method for identifying runtime issues.

## Topic 2: Time Check Pod with ConfigMap

### Objective

Created a BusyBox pod that periodically logs timestamps using a ConfigMap value.

### Steps Performed

1. Created the ConfigMap.

```bash
kubectl create configmap time-config \
--from-literal=TIME_FREQ=9 \
-n nautilus
```

2. Created the pod manifest.

3. Added:

* ConfigMap environment variable
* `emptyDir` volume
* Volume mount
* BusyBox container
* Logging loop

```sh
while true
do
    date >> /opt/itadmin/time/time-check.log
    sleep $TIME_FREQ
done
```

4. Applied the manifest.

```bash
kubectl apply -f time-check.yaml
```

5. Verified the pod.

```bash
kubectl get pods -n nautilus
```

6. Verified the environment variable.

```bash
kubectl exec -n nautilus time-check -- printenv TIME_FREQ
```

7. Verified log generation.

```bash
kubectl exec -n nautilus time-check -- cat /opt/itadmin/time/time-check.log
```

### Key Learning

* ConfigMaps are ideal for runtime configuration.
* `emptyDir` volumes provide temporary shared storage within a pod.
* Environment variables can be populated directly from ConfigMaps.
