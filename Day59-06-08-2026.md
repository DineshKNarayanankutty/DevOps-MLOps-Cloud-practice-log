## Task: Implement Batch Prediction Pipeline

### Objective

Complete the batch scoring workflow for the fraud-detection model by reading transaction data from a CSV file, generating predictions using a trained RandomForest model, and writing the results to a new CSV.

---

## Environment

```text

```

Files:

```text

```

Output:


---

## Step 1: Implement Batch Prediction Logic

Completed the batch scoring workflow.

```python
import joblib
import pandas as pd

MODEL_PATH = "/root/code/serving/model.pkl"
INPUT_CSV = "/root/code/serving/input.csv"
OUTPUT_CSV = "/root/code/serving/predictions.csv"

# Load trained model
model = joblib.load(MODEL_PATH)

# Read input CSV
df = pd.read_csv(INPUT_CSV)

# Select model features
features = df[
    [
        "amount",
        "hour",
        "num_tx_past_day"
    ]
]

# Predict fraud class labels
df["prediction"] = model.predict(features).astype(int)

# Save output
df.to_csv(
    OUTPUT_CSV,
    index=False
)

print(
    f"Wrote {len(df)} rows to {OUTPUT_CSV}"
)
```

---

## Step 2: Create an AMI

```hcl
resource "aws_ami_from_instance" "nautilus_ami" {
  name               = "nautilus-ec2-ami"
  source_instance_id = aws_instance.ec2.id

  tags = {
    Name = "nautilus-ec2-ami"
  }
}
```

---

## Step 3: Launch a New EC2 Instance

```hcl
resource "aws_instance" "new_ec2" {
  ami           = aws_ami_from_instance.nautilus_ami.id
  instance_type = "t2.micro"

  vpc_security_group_ids = [
    "sg-f76ca0c5c912fc227"
  ]

  tags = {
    Name = "nautilus-ec2-new"
  }

  depends_on = [
    aws_ami_from_instance.nautilus_ami
  ]
}
```

---

## Step 4: Outputs

# Linux

## Task: Troubleshoot HAProxy Load Balancer

### Objective

Restore the HAProxy service and ensure the load balancer correctly routes requests to backend application servers.

---

## Environment

Server:

```text
stlb01
```

Load Balancer:

```text
HAProxy
```

---

## Initial Issues

The HAProxy service failed to start.

Checked logs.

```bash
systemctl status haproxy

journalctl -xeu haproxy

haproxy -c -f /etc/haproxy/haproxy.cfg
```

---

## Issue 1: Invalid Load Balancing Algorithm

Found:

```cfg
backend static
    balance round
```

Corrected to:

```cfg
backend static
    balance roundrobin
```

---

## Issue 2: Invalid Frontend

Original configuration:

```cfg
frontend main *:80
```

Corrected to:

```cfg
frontend main
    bind *:80
```

---

## Issue 3: Duplicate Frontends

Detected multiple frontends binding to port **80**.

Removed unnecessary default frontend and retained:

```cfg
frontend http_front
    bind *:80
    default_backend app_servers
```

---

## Issue 4: Incorrect Backend Port

Initially configured:

```cfg
backend app_servers
    server app1 stapp01:5000 check
    server app2 stapp02:5000 check
    server app3 stapp03:5000 check
```

Backend servers were refusing connections.

Verified active listening ports.

```bash
ss -tlnp
```

Found Apache listening on:

```text
*:8080
```

Updated backend configuration.

```cfg
backend app_servers
    balance roundrobin
    server app1 stapp01:8080 check
    server app2 stapp02:8080 check
    server app3 stapp03:8080 check
```

---

## Step 5: Restart Service

```bash
systemctl restart haproxy
```

Validated configuration.

```bash
haproxy -c -f /etc/haproxy/haproxy.cfg
```

---

## Step 6: Verification

```bash
systemctl status haproxy

curl http://stlb01:80/
```

---

## Issues Encountered & Fixes

| Issue                   | Root Cause                                 | Resolution                                                                  |
| ----------------------- | ------------------------------------------ | --------------------------------------------------------------------------- |
| Service failed to start | Invalid `balance round` directive          | Changed to `balance roundrobin`                                             |
| Frontend syntax error   | Incorrect `frontend main *:80`             | Updated to use `bind *:80`                                                  |
| Duplicate frontends     | Two frontends bound to port 80             | Removed redundant frontend                                                  |
| Backend unavailable     | HAProxy pointed to wrong application ports | Verified service port using `ss -tlnp` and updated backend to port **8080** |

---

## Key Learning

* `haproxy -c` validates configuration before restarting the service.
* Layer 4 connection errors usually indicate an incorrect backend IP or port.
* Always verify the listening ports on backend servers before configuring HAProxy.
* Configuration validation significantly reduces troubleshooting time.
