## Provisioning an AWS Security Group Using Variables

### Objective

Provision an AWS Security Group while following Terraform best practices by separating configuration into reusable variable and resource files.

---

### Files Created

```text
variables.tf

main.tf
```

---

### variables.tf

```hcl
variable "KKE_sg" {
  description = "Security Group Name"
  type        = string
  default     = "xfusion-sg"
}
```

---

### main.tf

```hcl
provider "aws" {
  region = "us-east-1"
}

resource "aws_security_group" "sg" {
  name = var.KKE_sg

  tags = {
    Name = var.KKE_sg
  }
}
```

---

### Commands Executed

Initialize:

```bash
terraform init
```


### Objective

Securely expose a web application running on port **5000** by configuring `firewalld`.

---

### Server

```text
Application Server 3
```

---

### Step 1: Install Firewalld

```bash
sudo yum install -y firewalld
```

---

### Step 2: Enable Service

```bash
sudo systemctl enable --now firewalld
```

Verify:

```bash
sudo systemctl status firewalld
```

---

### Step 3: Configure Default Zone

```bash
sudo firewall-cmd \
--set-default-zone=public
```

Verify:

```bash
sudo firewall-cmd \
--get-default-zone
```

Output:

```text
public
```

---

### Step 4: Allow Port 5000

```bash
sudo firewall-cmd \
--permanent \
--zone=public \
--add-port=5000/tcp
```

Reload Configuration:

```bash
sudo firewall-cmd --reload
```

---

### Step 5: Verify Configuration

```bash
sudo firewall-cmd \
--zone=public \
--list-ports
```

Expected:

```text
5000/tcp
```

---

### Firewall Flow

```text

      ↓

      ↓

      ↓
TCP 5000 Allowed
      ↓
Web Application
```

---

### Key Learning

Firewalld uses zones to organize firewall rules. Permanent rule changes require a reload before they become active.

# Issues Encountered Today

### Azure Blob Upload

The Azure Portal could not directly access `/root/tempfile.txt` from the KodeKloud client host. The issue was resolved by uploading the file with the Azure CLI using the storage account name, container name, and storage account key.

### MLflow Bake-Off

The orchestrator selected the wrong winner because it sorted runs in ascending (`ASC`) order of `metrics.f1_score` and omitted the `model_type` field in the report. Updating the sort order to `DESC` and including the `tags.candidate` value fixed the report generation.
