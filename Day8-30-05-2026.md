# Terraform

## Create AMI from Existing EC2 Instance

### Task

Created an AMI named **devops-ec2-ami** from an already existing EC2 instance named **devops-ec2** using Terraform.

---

### Problem Encountered

Initial approach failed because the EC2 instance was not managed by Terraform.

Terraform validation error:

```text
Resources have not been created using terraform
```

---

### Solution

Use a Terraform data source to locate the existing EC2 instance.

### Edit main.tf

```bash
vi main.tf
```

### Terraform Configuration

```hcl
data "aws_instance" "devops_ec2" {
  filter {
    name   = "tag:Name"
    values = ["devops-ec2"]
  }
}

resource "aws_ami_from_instance" "devops_ec2_ami" {
  name               = "devops-ec2-ami"
  source_instance_id = data.aws_instance.devops_ec2.id
}
```

### Initialize Terraform

```bash
terraform init
```

### Apply Configuration

```bash
terraform apply -auto-approve
```

### Verify State

```bash
terraform state list
```

Expected:

```text
aws_ami_from_instance.devops_ec2_ami
```

---

### Simple Explanation

Instead of creating a new EC2 instance, Terraform searched for an existing instance named:

```text
devops-ec2
```

and then generated an Amazon Machine Image (AMI) from it.

---

### Why This Is Important

AMI creation is commonly used for:

* Golden Images
* Backup and Recovery
* Immutable Infrastructure
* Auto Scaling Launch Templates
* Disaster Recovery

Using Terraform allows AMI creation to be automated and version-controlled.
