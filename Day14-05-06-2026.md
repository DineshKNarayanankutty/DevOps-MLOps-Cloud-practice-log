## DevOps

### Apache Service Unavailability (Port 5003)

#### Task

One of the app servers reported Apache service unavailability. Apache needed to be running on **port 5003** on all app servers.

---

### Investigation

Checked Apache status on the faulty server:

```bash
systemctl status httpd
```

Output:

```text
Address already in use
AH00072: make_sock: could not bind to address
no listening sockets available
```

Verified Apache configuration:

```bash
grep -R "^Listen" /etc/httpd
```

Output:

```text
Listen 5003
```

Apache configuration was correct.

---

### Root Cause

Port **5003** was already occupied by another process.

Verified with:

```bash
ss -tulpn | grep 5003
```

The conflicting process was identified and stopped.

---

### Fix

Stopped the service occupying port 5003.

Restarted Apache:

```bash
systemctl restart httpd
systemctl enable httpd
```

---

### Verification

```bash
systemctl status httpd
```

Expected:

```text
active (running)
```

Check listening port:

```bash
ss -tulpn | grep 5003
```

Expected:

```text
*:5003 users:(("httpd"))
```

---

### Learning

When Apache reports:

```text
Address already in use
```

always verify:

```bash
ss -tulpn | grep <port>
```

before modifying configuration files.

# MLOps

## DVC Pipeline Troubleshooting

### Task

Fix a broken DVC pipeline in the `fraud-detection` project so that:

```text
process_data
    ↓
split_data
```

runs successfully using:

```bash
dvc repro
```

---

### Required Pipeline

#### Stage 1

```text
process_data
```

Dependencies:

```text
data/raw/transactions.csv
src/data/process_data.py
```

Output:

```text
data/processed/clean_transactions.csv
```

---

#### Stage 2

```text
split_data
```

Dependencies:

```text
data/processed/clean_transactions.csv
src/data/split_data.py
```

Outputs:

```text
data/processed/train.csv
data/processed/test.csv
```

---

### Correct dvc.yaml Structure

```yaml
stages:
  process_data:
    cmd: python src/data/process_data.py
    deps:
      - data/raw/transactions.csv
      - src/data/process_data.py
    outs:
      - data/processed/clean_transactions.csv

  split_data:
    cmd: python src/data/split_data.py
    deps:
      - data/processed/clean_transactions.csv
      - src/data/split_data.py
    outs:
      - data/processed/train.csv
      - data/processed/test.csv
```

---

### Validation

```bash
dvc repro
```

Then:

```bash
dvc status
```

Expected:

```text
Data and pipelines are up to date.
```

---

### Learning

DVC pipeline failures are commonly caused by:

* Missing dependencies
* Incorrect output paths
* Missing outputs
* Wrong stage names

# Terraform

## AWS IAM User Creation

### Task

Create IAM user:

```text
iamuser_jim
```

using Terraform.

---

### Terraform Configuration

```hcl
provider "aws" {
  region = "us-east-1"
}

resource "aws_iam_user" "iamuser_jim" {
  name = "iamuser_jim"
}
```

---

### Deployment

```bash
cd /home/bob/terraform

terraform init

terraform plan

terraform apply -auto-approve
```

---

### Verification

```bash
aws iam get-user --user-name iamuser_jim
```

---

### Learning

This task reinforced the most basic IAM resource provisioning pattern:

```hcl
resource "aws_iam_user" "user" {
  name = "username"
}
```

which serves as the foundation for future IAM tasks involving:

* Groups
* Policies
* Roles
* Access Keys
* MFA

* Check the service first.

  * Initialize
