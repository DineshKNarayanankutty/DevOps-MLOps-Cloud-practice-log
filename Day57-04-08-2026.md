# DevOps (Kubernetes)

## Task: Create a Pod Using Environment Variables

### Objective

Create a Kubernetes Pod that prints a greeting message using environment variables passed to the container and exits successfully without entering a restart loop.

---

## Environment

* Platform: Kubernetes
* Pod: `print-envars-greeting`
* Container: `print-env-container`
* Image: `bash`
* Restart Policy: `Never`

---

## Step 1: Create the Pod Manifest

Defined the Pod with three environment variables.

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: print-envars-greeting

spec:
  restartPolicy: Never

  containers:
  - name: print-env-container
    image: bash

    env:
    - name: GREETING
      value: "Welcome to"

    - name: COMPANY
      value: "DevOps"

    - name: GROUP
      value: "Group"

    command:
    - /bin/sh
    - -c
    - 'echo "$(GREETING) $(COMPANY) $(GROUP)"'
```

---

## Step 2: Deploy the Pod

```bash
kubectl apply -f pod.yaml
```

Verified the pod creation.

```bash
kubectl get pods
```

---

## Step 3: Verify Output

Checked the container logs.

```bash
kubectl logs -f print-envars-greeting
```

Expected output:

```text
Welcome to DevOps Group
```

---

## Verification Commands

```bash
kubectl get pods

kubectl describe pod print-envars-greeting

kubectl logs print-envars-greeting
```

---

## Key Learning

* Environment variables can be injected into containers using the `env` section.
* `restartPolicy: Never` prevents completed containers from restarting repeatedly.
* Container logs are useful for validating one-time execution jobs.

## Step 1: Implement the Prediction Endpoint

Completed the `/predict` handler.

Performed the following:

* Read the incoming JSON payload.
* Extracted `amount`, `hour`, and `num_tx_past_day`.
* Constructed a NumPy feature array.
* Used the pre-trained RandomForest model to generate predictions.
* Returned the prediction as JSON.

```
"""Flask fraud-detection prediction API.

Loads the pre-trained RandomForest at `/root/code/serving/model.pkl`
and exposes `/health` + `/predict` over HTTP.
"""
import joblib
import numpy as np
from flask import Flask, jsonify, request

MODEL_PATH = "/root/code/serving/model.pkl"
MODEL = joblib.load(MODEL_PATH)

app = Flask(__name__)


@app.route("/health")
def health():
    return jsonify({"status": "ok"}), 200


@app.route("/predict", methods=["POST"])
def predict():
    data = request.get_json()

    features = np.array([[
        data["amount"],
        data["hour"],
        data["num_tx_past_day"]
    ]])

    prediction = int(MODEL.predict(features)[0])

    return jsonify({"is_fraud": prediction}), 200


if __name__ == "__main__":
    app.run(host="0.0.0.0", port=8085)
```

# Terraform (AWS)

## Task: Provision Multiple EC2 Instances Using Terraform Count

### Objective

Provision multiple EC2 instances using Terraform's `count` meta-argument while maintaining a reusable and scalable configuration using variables, locals, data sources, and outputs.

---

## Files Created

```text
main.tf
variables.tf
locals.tf
terraform.tfvars
outputs.tf
```

---

## Step 1: Define Variables

Created configurable variables for instance count, instance type, key pair, and instance name prefix.

```hcl
variable "KKE_INSTANCE_COUNT" {
  type = number
}

variable "KKE_INSTANCE_TYPE" {
  type = string
}

variable "KKE_KEY_NAME" {
  type = string
}

variable "KKE_INSTANCE_PREFIX" {
  type = string
}
```

---

## Step 2: Retrieve Latest Amazon Linux 2 AMI

Used a Terraform data source to automatically retrieve the latest Amazon Linux 2 AMI and stored it in a local variable.

```hcl
data "aws_ami" "amazon_linux_2" {
  most_recent = true

  owners = ["amazon"]

  filter {
    name   = "name"
    values = ["amzn2-ami-hvm-*-x86_64-gp2"]
  }

  filter {
    name   = "virtualization-type"
    values = ["hvm"]
  }
}

locals {
  AMI_ID = data.aws_ami.amazon_linux_2.id
}
```

---

## Step 3: Provision Multiple EC2 Instances

Created three EC2 instances using the `count` meta-argument.

```hcl
provider "aws" {
  region = "us-east-1"
}

resource "aws_instance" "kke_instance" {
  count         = var.KKE_INSTANCE_COUNT
  ami           = local.AMI_ID
  instance_type = var.KKE_INSTANCE_TYPE
  key_name      = var.KKE_KEY_NAME

  tags = {
    Name = "${var.KKE_INSTANCE_PREFIX}-${count.index + 1}"
  }
}
```

Each instance was automatically named as:

```text
xfusion-instance-1
xfusion-instance-2
xfusion-instance-3
```

---

## Step 4: Assign Variable Values

Created `terraform.tfvars` to provide values for all input variables.

```hcl
KKE_INSTANCE_COUNT  = 3
KKE_INSTANCE_TYPE   = "t2.micro"
KKE_KEY_NAME        = "xfusion-key"
KKE_INSTANCE_PREFIX = "xfusion-instance"
```

---

## Step 5: Output Instance Names

Created an output variable to display the names of all EC2 instances after deployment.

```hcl
output "kke_instance_names" {
  value = [
    for instance in aws_instance.kke_instance :
    instance.tags["Name"]
  ]
}
```

---

## Verification Commands

```bash

terraform apply

terraform output kke_instance_names
```

Expected output:

```text

  "xfusion-instance-1",
  "xfusion-instance-2",
  "xfusion-instance-3"
]
```

---

## Key Learning

* The `count` meta-argument allows multiple identical resources to be created with a single resource block.
* Data sources dynamically fetch cloud resources such as the latest AMI, eliminating the need to hardcode AMI IDs.
* Local values improve readability by storing computed values for reuse.
* Variables make Terraform configurations reusable across different environments.
* Outputs expose useful deployment information, making it easy to reference created resources after provisioning.
