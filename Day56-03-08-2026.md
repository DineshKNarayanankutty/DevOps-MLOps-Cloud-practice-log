# DevOps (Kubernetes)

## Task: Deploy a Highly Available Nginx Application

### Objective

Deploy a highly available Nginx application on Kubernetes using a Deployment with multiple replicas and expose it through a NodePort Service.

---

## Environment

* Platform: Kubernetes
* Deployment: `nginx-deployment`
* Container: `nginx-container`
* Image: `nginx:latest`
* Replicas: `3`
* Service: `nginx-service`
* Service Type: `NodePort`
* NodePort: `30011`

---

## Step 1: Create the Deployment

Created a deployment with three replicas using the latest Nginx image.

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment

spec:
  replicas: 3

  selector:
    matchLabels:
      app: nginx

  template:
    metadata:
      labels:
        app: nginx

    spec:
      containers:
      - name: nginx-container
        image: nginx:latest
        ports:
        - containerPort: 80
```

---

## Step 2: Apply the Deployment

```bash
kubectl apply -f deployment.yaml
```

Verified deployment.

```bash
kubectl get deployments
```

Verified pods.

```bash
kubectl get pods -l app=nginx
```

Expected:

```text
3 Running Pods
```

---

## Step 3: Create the NodePort Service

Created a service exposing the deployment.

```yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx-service

spec:
  type: NodePort

  selector:
    app: nginx

  ports:
  - port: 80
    targetPort: 80
    nodePort: 30011
```

Applied the service.

```bash
kubectl apply -f service.yaml
```

---

## Step 4: Verification

Checked the service.

```bash
kubectl get svc nginx-service
```

Expected:

```text
80:30011/TCP
```

---

## Verification Commands

```bash
kubectl get deployment

kubectl get pods

kubectl get svc

kubectl describe deployment nginx-deployment

kubectl describe svc nginx-service
```

---

## Key Learning

* Deployments provide self-healing and replica management.
* Services provide stable networking to Pods.
* NodePort exposes an application on every Kubernetes node using a fixed port.

* `terraform apply -replace` recreates a resource without modifying configuration files.

* Always verify with `terraform plan` after replacement to ensure the state matches the configuration.
