## AWS

### IAM Policy Creation

#### Task

Create an IAM policy:

```text
iampolicy_jim
```

Requirements:

* Region: `us-east-1`
* Read-only EC2 access
* Allow viewing:

  * EC2 Instances
  * AMIs
  * Snapshots

---

### Solution

Created policy using:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ec2:Describe*"
      ],
      "Resource": "*"
    }
  ]
}
```

---

### Learning

The EC2 console relies primarily on:

```text
Describe APIs
```

such as:

```text
DescribeInstances
DescribeImages
DescribeSnapshots
DescribeVolumes
```

Using:

```text
ec2:Describe*
```

provides complete EC2 read-only visibility without modification rights.

## MLOps

### Git + DVC Dataset Versioning

#### Task

Create dataset versions using Git branches and DVC.

Requirements:

```text
Tag current state as v1.0
Create branch v2-improved
Use improved dataset
Re-run pipeline
Restore original dataset
```

---

### Versioning Workflow

Tag baseline:

```bash
git tag v1.0
```

Create feature branch:

```bash
git checkout -b v2-improved
```

Replace dataset:

```bash
cp transactions_v2.csv transactions.csv
```

Update DVC tracking:

```bash
dvc add data/raw/transactions.csv
```

Rebuild:

```bash
dvc repro
```

Commit changes:

```bash
git add .
git commit -m "Use improved dataset"
```

---

### Restore Original Dataset

Return to main:

```bash
git checkout main
```

Restore tracked files:

```bash
dvc checkout
```

---

### Why This Matters

Without DVC:

```text
dataset_final.csv
dataset_final_v2.csv
dataset_final_v3.csv
```

becomes difficult to manage.

With Git + DVC:

```text
Git
  ↓
Code Version

DVC
  ↓
Dataset Version

Together
  ↓
Full Reproducibility
```

---

Every model can be tied to:

```text

Metrics
```

allowing:

