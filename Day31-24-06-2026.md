# DevOps

## Git Stash Restoration

### Objective

Restore previously stashed work from:

```text
stash@{1}
```

and push it to origin.

Repository:

```text
/usr/src/kodekloudrepos/demo
```

---

### Commands Used

Navigate:

```bash
cd /usr/src/kodekloudrepos/demo
```

List stashes:

```bash
git stash list
```

Example:

```text
stash@{0}
stash@{1}
stash@{2}
```

---

### Restore Required Stash

```bash
git stash apply stash@{1}
```

---

### Verify Changes

```bash
git status
```

Optional:

```bash
git diff
```

---

### Commit

```bash
git add .

git commit -m "Restore stashed changes"
```

---

### Push

```bash
git push origin master
```

---

## Understanding This Task

### Why Stash Exists

Instead of committing unfinished work:

```text
Developer
      ↓
Unfinished Changes
      ↓
git stash
      ↓
Temporary Storage
```

---

### Stash Stack

```text
stash@{0}
   ↓
Newest

stash@{1}
   ↓
Older

stash@{2}
   ↓
Older
```

---

### apply vs pop

Apply:

```bash
git stash apply stash@{1}
```

Result:

```text
Restore Changes
Keep Stash
```

---

Pop:

```bash
git stash pop stash@{1}
```

Result:

```text
Restore Changes
Delete Stash
```

---

### Workflow

```text
Developer Work
      ↓
git stash
      ↓
stash@{1}
      ↓
git stash apply
      ↓
Changes Restored
      ↓
git add
      ↓
git commit
      ↓
git push
```

---

### Real-World Usage

Used during:

```text
Production Fixes
Branch Switching
Code Reviews
Emergency Hotfixes
```

# MLOps

## Config-Driven Training Pipeline Repair

### Objective

Fix broken training configuration and execute successful MLflow training run.

---

### Project

```text
/root/code/fraud-detection
```

---

### Broken Configuration

Original:

```yaml
model:
  type: RandomForest

data:
  target_column: target

output:
  model_path: /root/code/model.pkl
```

---

### Problem 1

Invalid estimator:

```yaml
type: RandomForest
```

Supported values:

```text
RandomForestClassifier
GradientBoostingClassifier
LogisticRegression
```

Fix:

```yaml
type: RandomForestClassifier
```

---

### Problem 2

Invalid target column:

```yaml
target_column: target
```

Dataset columns:

```text
amount
hour
num_tx_past_day
is_fraud
```

Fix:

```yaml
target_column: is_fraud
```

---

### Problem 3

Wrong output path:

```yaml
model_path: /root/code/model.pkl
```

Fix:

```yaml
model_path: /root/code/fraud-detection/models/model.pkl
```

---

### Final Configuration

```yaml
model:
  type: RandomForestClassifier
  n_estimators: 100
  max_depth: 5
  random_state: 42

data:
  train_path: /root/code/fraud-detection/data/train.csv
  target_column: is_fraud

output:
  model_path: /root/code/fraud-detection/models/model.pkl

mlflow:
  tracking_uri: http://localhost:5000
  experiment_name: fraud-detection
```

---

### Execute Training

```bash
cd /root/code/fraud-detection

python3 src/models/train.py
```

---

### Verification

Model file:

```bash
ls -l /root/code/fraud-detection/models/model.pkl
```

MLflow:

```text
Experiment:
fraud-detection
```

Expected:

```text
1 Successful Run
```

with hyperparameters logged.

---

### Key Learning

Config-driven ML pipelines separate:

```text
Code
     ↓
Configuration
```

allowing parameter changes without modifying Python code.

# Linux

## XML String Replacement

### Objective

Replace every occurrence of:

```text
String
```

with:

```text
Echo-Location
```

inside:

```text
/root/nautilus.xml
```

---

### Command Used

```bash
sed -i 's/String/Echo-Location/g' /root/nautilus.xml
```

---

### Verification

Search:

```bash
grep "Echo-Location" /root/nautilus.xml
```

View file:

```bash
cat /root/nautilus.xml
```

---

## Understanding This Task

Command:

```bash
sed -i 's/String/Echo-Location/g' /root/nautilus.xml
```

Breakdown:

```text
s
↓
Substitute

String
↓
Old Text

Echo-Location
↓
New Text

g
↓
Global
(All Occurrences)
```

---

### Flow

```text
Original XML
      ↓
Contains:
String
      ↓
sed Command
      ↓
Every Occurrence Replaced
      ↓
Echo-Location
```

---

### Why Use sed?

Advantages:

```text
Fast
Scriptable
Works on Large Files
No Manual Editing
```

Common DevOps use cases:

```text
Config Updates
Template Processing
CI/CD Pipelines
Infrastructure Automation
```
