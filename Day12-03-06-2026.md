# DevOps

## Apache Service Troubleshooting (Port 6400)

### Task

Apache on **App Server 1** was reported as unreachable on port **6400**.

---

### Initial Verification

From Jump Host:

```bash
telnet stapp01 6400
```

Output:

```text
No route to host
```

While:

```bash
telnet stapp02 6400
telnet stapp03 6400
```

worked successfully.

---

### Check Apache Service

```bash
ssh tony@stapp01
sudo su -

systemctl status httpd
```

Output:

```text
Failed to start The Apache HTTP Server
Address already in use
```

---

### Investigate Port Conflict

```bash
ss -tulpn | grep 6400
```

Output:

```text
127.0.0.1:6400 users:(("sendmail"))
```

---

### Root Cause #1

`sendmail` was already using port **6400**, preventing Apache from starting.

---

### Fix

```bash
systemctl stop sendmail
systemctl disable sendmail

systemctl start httpd
systemctl enable httpd
```

---

### Verify Apache

```bash
systemctl status httpd

ss -tulpn | grep 6400
```

Output:

```text
*:6400 users:(("httpd"))
```

Apache successfully started.

---

### Remaining Issue

From Jump Host:

```bash
curl http://stapp01:6400
```

Output:

```text
No route to host
```

---

### Investigate Firewall

```bash
iptables -L -n
```

Output:

```text
ACCEPT established
ACCEPT icmp
ACCEPT loopback
ACCEPT ssh

REJECT all
```

No rule existed for port **6400**.

---

### Root Cause #2

iptables was blocking inbound traffic to port 6400.

---

### Final Fix

```bash
iptables -I INPUT 5 -p tcp --dport 6400 -j ACCEPT
```

---

### Verification

```bash
curl http://stapp01:6400
```

Successful response received from Jump Host.

---

### Why This Is Important

This was a real-world layered troubleshooting exercise:

1. Service failure
2. Port conflict
3. Firewall restriction
4. End-to-end validation

# Terraform

## Public S3 Bucket Creation

### Task

Create public bucket:

```text
datacenter-s3-10538
```

in:

```text
us-east-1
```

---

### Initial Issue

Terraform failed during initialization.

Error:

```text
Invalid multi-line string
Extraneous label for resource
```

---

### Root Cause

Resource block typo:

Incorrect:

```hcl
resource "aws_s3_bucket" "datacenter_s3 {
```

Correct:

```hcl
resource "aws_s3_bucket" "datacenter_s3" {
```

Missing closing quote caused Terraform to interpret the rest of the file as a string.

---

### Final Terraform Configuration

```hcl
provider "aws" {
  region = "us-east-1"
}

resource "aws_s3_bucket" "datacenter_s3" {
  bucket = "datacenter-s3-10538"
}

resource "aws_s3_bucket_public_access_block" "datacenter_s3" {
  bucket = aws_s3_bucket.datacenter_s3.id

  block_public_acls       = false
  block_public_policy     = false
  ignore_public_acls      = false
  restrict_public_buckets = false
}

resource "aws_s3_bucket_acl" "datacenter_s3" {
  depends_on = [aws_s3_bucket_public_access_block.datacenter_s3]

  bucket = aws_s3_bucket.datacenter_s3.id
  acl    = "public-read"
}
```

# Key Lessons Learned

### DevOps

* A service may fail because another process owns the required port.
* `ss -tulpn` is one of the fastest ways to identify port conflicts.
* "No route to host" often points to firewall rules rather than application failures.

### MLOps

* DVC can use any S3-compatible backend, not just AWS S3.
* SeaweedFS is commonly used as a lightweight object store for ML artifacts.

### Terraform

* A single missing quote can produce dozens of Terraform parser errors.
* Read the **first error** carefully; subsequent errors are often side effects.
* Public S3 buckets require both ACL configuration and public access block settings to be handled correctly.
